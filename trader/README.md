# 自己学習型マルチアセット自動売買ツール

仮想通貨 (ミームコイン含む)・FX・株式を自律的に売買するツールです。メインはスキャルピングと短期売買で、中期・長期にも対応しています。

インターネットから集めた情報で戦略を立てます。損益が出るたびに要因を分析し、その結果を次の判断に反映します (自己学習)。

> **重要**
> - 既定は**ペーパートレード (仮想売買)** です。実際の資金は動きません。
> - 利益は保証されません。スキャルピングは手数料とスプレッドの影響が非常に大きく、多くの戦略はコスト負けします。
> - 実弾で運用する前に、必ず実データでバックテストとペーパー運用を十分に行ってください。少額から始めてください。
> - 自分の資金を自分で運用する用途を想定しています。他人の資金を運用したり、売買シグナルを有償で提供したりする場合は、金融商品取引法上の登録 (投資運用業・投資助言業など) が必要になることがあります。

## 全体の仕組み

### 戦略

| 時間軸 | 戦略 ID | 内容 |
|---|---|---|
| スキャルピング (1 分足) | `scalp_obi` | 板の厚みの偏り・microprice・約定フロー (板情報が必要) |
| | `scalp_vwap_revert` | VWAP からの乖離の逆張り (レンジ相場向け) |
| | `scalp_momentum_burst` | 出来高急増を伴う直近高値・安値のブレイク |
| | `scalp_micro` | 5〜10 分で利確・損切りする超短期のモメンタム (成行。コストの条件を満たすときだけ) |
| | `scalp_rebound` | 15 分足が下降トレンドのときの、1 分足の売られ過ぎからの反発を買う (買いのみ。**既定で観測専用**) |
| | `scalp_pullback` | 15 分足 EMA20 の傾きで方向を決め、上昇中の 1 分足の押しを買い、下降中の戻りを売る (暗号資産。売りは空売りできるとき。損切りは押しの極値の外側、利確は損切り幅の 2 倍、保有 10〜30 分。コスト条件を満たすときだけ) |

`scalp_micro` がコストの条件 (利確幅・損切り幅・期待値) で見送ったシグナルは、「見るだけ」の仮想トレード (理由 `strategy_filter:cost` / `:spread` / `:edge`) として記録します。発注・リスク判定・腕の学習には使いません。
`scalp_rebound` は既定で観測専用 (`OBSERVE_ONLY_STRATEGIES=scalp_rebound`) です。シグナルは発注せず、仮想トレード (理由 `observe_only`) としてだけ記録します。効果を確かめてから `OBSERVE_ONLY_STRATEGIES=` (空) にすると実際に取引します。
`npm run report` の「超短期 (scalp_micro / scalp_rebound) の答え合わせ」の表は、戦略・見送り理由ごとの利確到達率と、値動きがランダムなときの勝率 p0 を並べます。利確到達率が p0 を安定して上回るなら、値動きに優位性があります。
平均R (コスト前) が正でも平均純R が負なら、手数料が利益を上回っています。件数が少ないうちは偶然の影響が大きいので判断しないでください。

| | `short_rsi_revert` | RSI + ボリンジャーバンドの逆張り |
| | `short_breakout` | ドンチャン・ブレイクアウト + 出来高確認 |
| 中期 (4 時間足) | `mid_trend_follow` | EMA20/50 + MACD、ATR トレーリング |
| 長期 (日足) | `long_momentum` | 90 日モメンタム + 200 日 SMA フィルター |

### 「収集した情報」を学習に使う仕組み

1. エントリー時に、判断に使った情報 (どの情報源がどちら向きだったか) をトレード記録に保存します。
2. 決済後、情報の向きと実際の値動きが一致したかを情報源ごとに集計します。
3. 一致率に応じて、情報源の重み (0.2〜2.0) を自動更新します。
4. 次回の情報分析では、この重みで情報源を重み付けします。
5. 資産クラスごとに「情報が損益に効いているか」も測り、情報バイアスが戦略に与える影響の強さを自動で調整します。

### 取引が無い間も学習する仕組み

実際の取引は件数が少ないため、次の 3 つで学習の材料を増やします。どれも発注・リスク判定・建玉管理には関与しません (記録して後で答え合わせをするだけです)。

- **仮想トレード (見送ったシグナルの答え合わせ)**
  - 戦略が売買シグナルを出したのに発注しなかったもの (コスト比フィルター、リスク判定の拒否、方向バイアスとの不一致、腕の無効化、スコア負けなど) を仮想のトレードとして記録します。
  - 毎ティックの気配で損切り・利確・時間切れを判定し、約定ずれ (片道 2bps) とコストを差し引いた R で結果を出します。
  - 結果は、同じ腕 (戦略×相場環境×資産クラス) の配分の更新に**重み 0.25** (実際の取引は 1) で反映します。
  - 戦略自身がコストで見送ったシグナル (`strategy_filter:*`) は観測専用で、保存だけして腕・情報の効き具合には使いません。
  - リスク管理の停止中 (日次損失の上限・キルスイッチ・状態不明の注文による新規停止) に記録した仮想トレードは、学習には使いません。
  - 未決済の仮想トレードは再起動後も続けます。決済済みの記録は 30 日で削除します。
- **ニュースと値動きの答え合わせ**
  - 強弱がはっきりしたニュース (監視銘柄に関係するもの) を記録し、15 分・1 時間・4 時間後の値動きと比べます。
  - ノイズの範囲 (1 分足の ATR 比と往復コストの大きい方) に収まる動きは、当たりにも外れにも数えません。
  - 当たり・外れを情報源の信頼度に**重み 0.3** で反映します。
- **値動きの予想**
  - 監視銘柄ごとに 5 分ごと、15 分・1 時間・4 時間後の「上がる / 下がる / ほぼ動かない」と値幅を予想します。特徴量はトレンド・モメンタム・平均回帰・ニュースのバイアス・戦略の合意で、確定足だけから作ります (先読みしません)。
  - 期限に実際の値動きと答え合わせをし、オンラインのロジスティック回帰で重みを更新します。
  - 予想がエントリーに効くのは、(予想時間, 資産クラス) ごとに、方向を当てた回数が 100 件以上あり、的中率が 50% を統計的に有意に上回る (片側 95%。重なる予想は独立でないため補正) ときだけです。そのときに限り、シグナルと予想の向きが一致すれば最大 1.2 倍、逆なら最小 0.7 倍にエントリーサイズを調整します。有意でない間・予想が「ほぼ動かない」とき・予想が古いときは 1 倍で、まったく影響しません。サイズは最終的にリスク管理の上限 (1.5 倍) の範囲に収まります。

### 学習状態は paper / live で別

腕・パラメータ・調整履歴・情報源の信頼度・ニュースの答え合わせ・値動きの予想・仮想トレードは、mode (paper / live) ごとに別のキーで保存します。paper の学習結果が live に混ざることはありません。

- 旧バージョンのデータ (mode の区別が無かったもの) は、初回起動時に **paper 用へ引き継ぎ**ます (旧データは消しません)。
- **live は初期状態から**始まります (腕・信頼度は事前分布、パラメータはコードの既定値)。
- `report` は、現在の `TRADING_MODE` で解決された mode (paper / live) の学習状態を表示します。

### paper でだけ空売りを再現して学習する (`PAPER_SIMULATE_SHORT`)

bitbank などの現物 (ccxt の spot) は空売りできないため、live では売りのシグナルを出しません。paper では、空売りの成績も学習させるために「売りで負の建玉を持ち、買い戻しで決済する」空売りを再現します (既定で有効)。**live では空売りしません** (設定に関わらず、live の銘柄・リスク管理・実口座の発注の経路は従来のままです)。

- **対象**: 取引所で空売りできない暗号資産 (`allowShort=false` の `crypto`)。ミームコイン (`meme`) と DEX の銘柄は、流動性が薄く実際には借りられないため対象外です。FX・株など取引所で空売りできる銘柄は従来どおりです。
- **約定と会計**: 売りで負の建玉を持ち、建玉代金を余力から拘束します (証拠金)。買い戻したときに、借入コスト = 建玉代金 (平均建値 × 数量) × `PAPER_SHORT_BORROW_RATE_DAILY` × 保有日数 (日割り) を手数料として計上します。保有中の未払い分は評価額から差し引きます。
  - 既定の日率 0.04%/日は bitbank の信用取引の手数料・金利を想定した**仮の値**です。**実際の料率 (と日数の数え方) は取引所で確認**してください。
- **リスク管理**: 空売りもリスク管理 (`evaluateEntry`) をすべて通します。損切りはエントリー価格より上に置き、最大保有数・1 銘柄上限・資産クラス別の上限に含めます。
- **学習の分離**: 空売り (paper 再現) の取引と仮想トレードは、別の腕 `<戦略>|<レジーム>|<資産クラス>|short` で学習します。買いの腕 (従来のキー) の配分・停止には混ざりません。
  - パラメータ (買い・売り共通) の調整・事後評価と振り返りには使いません (live に持ち込む調整は live で実行できる取引だけで判断するため)。情報源の信頼度・情報の効き具合も更新しません。値動きの予想の「適用した予想」にも数えません。
  - 計画の片側バイアスは、paper では対象の銘柄を「売りのみ」にできます (live では従来どおり「両方」+ リスク縮小)。
- **表示**: `report`・`simulate`・ダッシュボード (取引タブ・学習タブ) で、成績を「買い」「売り (取引所で可能な空売り)」「空売り (paper 再現)」に分けて表示します。**live で実際にできる成績は「空売り (paper 再現)」を除いたもの** (現物なら買いのみ) です。
- 無効にするには `PAPER_SIMULATE_SHORT=false` にします (従来の動作)。保有中の再現した空売りは、無効にした後も決済 (買い戻し) だけはできます。

## 相場構造 (ダウ理論) フィルター

戦略のシグナルを、相場構造 (高値・安値の切り上げ / 切り下げ) の目線と照らして絞ります。既定で有効です (`STRUCTURE_MODE=filter`)。`off` にすると従来と完全に同じ動きです。

- **確定足だけ**を使い、各時間足で直近 300 本を見ます。スイング点 (高値・安値) は N 本後に確定するので、後から書き換わりません。
- 上位足の確認も確定足だけです (1m→15m、5m/15m→1h、1h→4h、4h→1d、1d→1w)。週足は直近 300 本の日足から作り、形成中の週は使いません。
- 目線と逆のシグナル、上位足と食い違うシグナル、ちゃぶつき (目線が短期間に何度も反転) などは見送ります。見送りは観測専用の仮想トレード `strategy_filter:structure_*` (bias / mtf / chop / none / weak / po / stop) として記録するだけで、学習には使いません。
- 既定の対象は `scalp_momentum_burst` / `scalp_micro` / `short_ema_trend` / `short_breakout` / `mid_trend_follow` / `long_momentum` / `meme_momentum` です。逆張りや反発を狙う `scalp_obi` / `scalp_vwap_revert` / `short_rsi_revert` / `scalp_rebound` / `scalp_pullback` は、目線と逆に入ること自体が設計なので対象外です。
- 構造の損切り (`STRUCTURE_STOP_MODE=structure`) は、損切りを押し安値 (売りは戻り高値) の外側 ± ATR × バッファへ動かすだけです。サイズはリスク管理が決め、期待値は増やしません。新しい損切り幅が元の 0.5 倍未満・3 倍超・0.5 ATR 未満のとき、または利確が不正になるときは見送ります。
- 起動時に、未知の戦略 ID と、`purist` での `STRUCTURE_EXIT_ON_WEAKENING` を警告します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `STRUCTURE_MODE` | `filter` | `off` / `filter` |
| `STRUCTURE_STRATEGIES` | 上記 7 戦略 | 対象の戦略 ID (カンマ区切り) |
| `STRUCTURE_PIVOT_N` | 6 | スイング点の確定に使う本数 (3〜20) |
| `STRUCTURE_BREAK_MODE` | `close` | 高値・安値の更新を終値 (`close`) かヒゲ (`wick`) で判定 |
| `STRUCTURE_BIAS_METHOD` | `method1` | 目線の判定方法 (`method1` / `method2` / `both`) |
| `STRUCTURE_REVERSAL_MODE` | `purist` | 転換の判定 (`purist` / `conservative`) |
| `STRUCTURE_USE_MTF` | `true` | 上位足の確認を使う |
| `STRUCTURE_USE_PERFECT_ORDER` | `false` | 移動平均のパーフェクトオーダーも条件にする |
| `STRUCTURE_STOP_MODE` | `existing` | `existing` (戦略の損切り) / `structure` |
| `STRUCTURE_STOP_ATR_BUFFER` | 0.3 | 構造の損切りの ATR バッファ |
| `STRUCTURE_EXIT_ON_REVERSAL` | `false` | 目線の転換で決済する |
| `STRUCTURE_EXIT_ON_WEAKENING` | `false` | 目線の弱まりで決済する |
| `STRUCTURE_CHOP_M` | 50 | ちゃぶつき判定の本数 (5〜300) |
| `STRUCTURE_CHOP_R` | 3 | M 本の間の目線の反転回数がこの値以上なら新規を止める |

```bash
# 全戦略のバックテスト (--source synthetic / ccxt / gmo)
npm run backtest -- --strategy all --source synthetic
# フィルターの効果の比較: A (ラッパーなし) 〜 G (conservative) を区間ごとに比べる
npm run backtest -- --structure-compare --strategy all --folds 5 --days 60 --source ccxt
# N=4/6/10 での頑健性の確認 (N を調整し続けるためのものではありません)
npm run backtest -- --structure-compare --strategy short_ema_trend --pivot-sweep
# 各時刻の目線・押し安値/戻り高値・choppiness を見る
npm run trader -- regime --symbol BTC/JPY --hours 3
```

- 取引が 30 回未満の区間は「回数不足」と表示し、判断に使いません。
- `regime` は目線・押し安値 / 戻り高値・choppiness も表示します。`simulate` は理由別の見送り数を表示します。

## 指値 (maker) でのエントリー

新規エントリーを指値にして、手数料を maker にします (`LIMIT_ENTRY`、既定 `true`)。

- 買いは最良の買い気配、売りは最良の売り気配に置きます。優先順位は、シグナル自身の指値価格 > 戦略の指定 (`entryOrder`) > 設定です。`scalp_micro` は成行です。
- post-only は、対応する取引先 (ペーパー) だけで使います。GMOコインは公式資料上、post-only (SOK) が現物のみとされている (要確認) ため、レバレッジ取引は通常の指値です (GMOのレバレッジ取引の手数料は maker / taker とも 0)。
- リスク判定は発注前に、指値価格でサイズを決めて行います。
- 約定待ちの間は、その銘柄の新規エントリーを止めます。期限切れ・反対のシグナル・損切り価格の通過・新規を止める条件 (停止・日次停止・キルスイッチ・状態不明の注文・口座取得不可・気配の古さ) で取り消します。
- 取り消したら照会で確認します。取消と注文の消滅を確認できるまで追跡から外しません。確認できない場合は状態不明として扱い、新規を止めます。取引所に余分な建玉があれば異常 (キルスイッチ) にします。
- 一部約定は、約定した数量の建玉にします。最小数量未満の端数は追跡せず、監査ログ `limit.dust_entry` に残します。
- 期限切れで約定しなかったものは、仮想トレード `limit_unfilled` (重み 0.25) として記録します。
- ペーパーの約定は、気配が指値を通り抜けたときだけです (触れただけでは約定しません)。手数料は maker です。バックテストも、次の足から高値・安値が指値を通過したときだけ約定し、同じ足では損切りを優先します。検証と CLI のバックテストも、現在の mode と同じ前提です。
- `npm run status` に指値の設定と約定率、`npm run report` に注文種別ごとの成績・maker/taker 手数料の内訳・平均手数料率・指値の約定率を表示します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `LIMIT_ENTRY` | `true` | 新規エントリーを指値にする |
| `LIMIT_ENTRY_TIMEOUT_MS` | 主時間足の長さ (20 秒〜15 分) | 指値の有効期限 (1000〜86400000 ミリ秒) |
| `LIMIT_TAKE_PROFIT` | `false` | 約定後に利確の指値 (reduceOnly) を板に置く。**paper のみ**。live では無視し、起動時に警告します。成行で決済する前に、取り消して確認します |

## エントリー頻度の目標 (テンポ) と最大保有

`TARGET_ENTRIES_PER_HOUR` を設定すると、1 時間あたりのエントリー回数が目標に足りないときだけ、条件を少しずつ緩めます (既定 0 = 無効。無効なら従来と同一です)。

> **注意**
> - **リスクは上がります。** 条件を緩めて入るので、質の低いエントリーが増えます。
> - エントリーが増えても、利益が増えるとは限りません。手数料とスプレッドの負担が増えて、成績が悪化することがあります。
> - 先にペーパーで効果を確認してください。
> - 高頻度にするなら `VENUES=gmo` を推奨します。bitbank は taker 手数料が高く、1 分足のスキャルピングはコストの条件を満たせません。

- **テンポ** (0〜1) = 不足 (1 − 直近 1 時間のエントリー数 / 目標) × 待ち (最後のエントリーから 60/目標 分までは 0、その 2 倍で 1)。ティックごとに 1 回計算し、**新規エントリーの判断にだけ**使います。決済・バックテスト・パラメータ検証には使いません。
- **緩めるもの** (これだけ): 戦略のコスト倍率 (1.5 に向けて)、`scalp_pullback` の閾値 (RSI の距離・15 分足の傾きの下限・押しの深さ)、リスク管理のコスト比 (`TEMPO_MIN_EDGE_TO_COST` に向けて。1 未満にはしません)。コストを差し引いた期待値のシグナルは、テンポのときにコストを二重に数えません。
- **緩めないもの**: クールダウン、損切り幅の制限、最大保有、リスク管理のそのほかの判定。
- **探索**: ペーパーでは常に、live では `TEMPO_ALLOW_LIVE_EXPLORE=true` のときだけ。コスト差引後の期待値の下限を (テンポ × 往復コスト) だけ下げ、期待値が 0 以下のエントリーはサイズを `TEMPO_EXPLORE_SIZE` 倍にして「探索」として記録します。NaN は常に拒否します。
- **上限**: 直近 1 時間のエントリーが ceil(目標 × `TEMPO_CAP_MULTIPLIER`) に達したら、新規を止めて仮想トレード `tempo_cap` を記録します。数えるのは約定して建玉になったときで、再起動後もこの mode の直近 1 時間の取引と建玉から復元します。
- **最大保有** (`MAX_HOLD_MINUTES`、0 = 無効、5〜1440): 中期・長期の戦略は新規を発注せず、仮想トレード `hold_limit` (観測専用と同じ扱い。重み 0.25、腕は止めません) として記録します。ほかの戦略は最大保有をこの分数までに縮めます。保有中の建玉は変えません。バックテストと検証も同じ値を使います (中期・長期は縮めず、表に「運用では発注しない」と注記)。

| 変数 | 既定 | 内容 |
|---|---|---|
| `TARGET_ENTRIES_PER_HOUR` | 0 | 目標のエントリー回数/時 (0〜60。0 で無効) |
| `MAX_HOLD_MINUTES` | 0 | 最大保有の分数 (0 で無効、5〜1440) |
| `TEMPO_MIN_EDGE_TO_COST` | 1 | テンポ時のコスト比の下限 (1 以上) |
| `TEMPO_CAP_MULTIPLIER` | 2 | 上限 = 目標 × この値 (切り上げ) |
| `TEMPO_EXPLORE_SIZE` | 0.5 | 探索のサイズ倍率 |
| `TEMPO_ALLOW_LIVE_EXPLORE` | `false` | live でも探索する |

```bash
# 1 時間 6 回を目標、最大保有 30 分で、合成データを 2 日分ペーパー運転
TARGET_ENTRIES_PER_HOUR=6 MAX_HOLD_MINUTES=30 npm run simulate -- --days 2
```

- `status` とダッシュボードに、目標・直近 1 時間の回数・テンポ・上限到達・探索の可否・最大保有を表示します。
- `report` に、探索 / 通常 (テンポ有効) / 通常 (テンポ無効) の件数・勝率・純損益・平均 R の表を出します。
- `simulate` は、エントリー/時・平均保有・テンポ・見送り件数を表示します。

## 使い方

```bash
# ネット接続なしで全体の動きを確認 (合成データ + 仮想時計で高速にペーパー運転)
npm run simulate -- --days 3
# --hours N (時間単位。--days と併用可) / --seed 1 (乱数のシード) / --step 15 (仮想時計の刻み, 秒)
# --db <ファイル> (既定は memory。DB_PATH と同じファイルは使えません)
npm run simulate -- --hours 12 --seed 7 --step 30 --db ./data/sim.db

# バックテスト (全戦略の比較)
npm run backtest -- --strategy all --days 30
# 取引所の実データでのバックテスト (CCXT_EXCHANGE の履歴を取得)
npm run backtest -- --strategy short_ema_trend --symbol BTC/JPY --source ccxt --days 60
# 合成データの乱数のシードを変える (既定 1)
npm run backtest -- --strategy all --days 30 --seed 5

# 相場構造フィルターの比較 (詳しくは「相場構造 (ダウ理論) フィルター」)
npm run backtest -- --structure-compare --strategy all

# 情報収集を 1 回実行して内容を確認
npm run trader -- intel

# 実時間で起動 (既定は paper)。ダッシュボード: http://127.0.0.1:8787
npm start

# 成績・学習状態のレポート (現在の mode の学習状態を表示) / 状態確認 / 停止の解除
npm run report
npm run status
npm run trader -- resume

# 約定待ち・状態不明の注文の一覧と、手動での確定 (live 用)
npm run trader -- orders list      # 引数なしの `orders` も同じ
npm run trader -- orders resolve <clientId> --none                                  # 約定していなかった
npm run trader -- orders resolve <clientId> --filled --qty <数量> --price <価格>    # 約定していた
```

- `orders resolve` は、状態不明 (escalated) になった注文だけが対象です。それ以外の保留中の注文を確定させるには `--force` が必要です。`--none` (約定していなかった) で取消に失敗したときは確定せず、保留のまま建玉の照会で確定させます。
- `resume` は、動いているエンジンにも次のティック (数秒以内) で反映されます。再起動は不要です。
- `VENUES=synthetic` だけで起動した場合、記録は `DB_PATH` とは別のファイル (`trader-synthetic.db` のように `-synthetic` が付いたもの) に保存されます。合成データの成績が実データの学習に混ざらないようにするためです。`simulate` は `DB_PATH` とこのファイルのどちらにも書き込みません。
- paper と live の保有ポジション・停止状態は別々に記録されます。paper で作ったポジションを live で決済しようとすることはありません。

## ダッシュボード

`npm start` で起動すると、既定では http://127.0.0.1:8787 (`DASHBOARD_HOST` / `DASHBOARD_PORT`) に閲覧専用の画面が開きます。暗いターミナル風の画面で、5 秒ごとに更新されます。上部のタブで次のように切り替えます。

| タブ | 見えるもの |
|---|---|
| BOARD (ボード) | 全体を一覧する画面。ENGINE LOG (判断の記録: エントリー・決済・見送り・計画・発注・リスク・学習の各イベントを新しい順に表示)、チャート (銘柄と時間足を切り替え。選べる時間足は 1 分・5 分・15 分・1 時間・4 時間・日足のうち、エンジンが扱っているもの)、戦略×相場環境ごとの腕の成績ヒートマップ、戦略ごとの配分倍率、指標、集めた情報の粒子の雲、今回の稼働の戦略別成績、SIGNAL STACK、損益、戦略別の勝率、リスク予算、手数料 |
| 概要 | 評価額、リスク状態、評価額の推移 |
| 強気・弱気 | 資産別の強気・弱気 (バイアス)、戦略計画と集めた情報 |
| ポジション | 保有中のポジション |
| 取引 | 直近のトレードと損益要因、戦略別の成績 |
| 学習 | 損益要因の集計、教訓、パラメータ調整の履歴、情報源の信頼度、腕の成績、仮想トレード (見送ったシグナルの答え合わせ)、ニュースと値動きの答え合わせ、値動きの予想の答え合わせ |

**SIGNAL STACK** は、監視銘柄ごとのカード (WATCH) と、直近のエントリー・決済・見送り (最新 5 件) を新しい順に並べます。WATCH カードには現在値、計画の方向、強気・弱気と信頼度、そして時間ごと (15m / 1h / 4h) の値動きの予想を出します。

- 予想は、方向 (▲ 上 / ▼ 下 / ― ほぼ動かない)、その方向の確率 (%)、値幅 (±%) です。カーソルを合わせると、上昇確率・的中率・予想の根拠 (特徴量ごとの寄与) が出ます。
- 的中率の件数が少ない間は「学習中 · n=件数」と表示します。
- 予想がエントリーサイズに反映されている (統計的に有意と確認できた) ときは LIVE バッジが付きます。

**状態バッジ** (画面上部) と警告欄:

| 表示 | 色 | 意味 |
|---|---|---|
| ACTIVE 稼働中 | 緑 | 通常 |
| KILL SWITCH / HALTED 停止中 | 赤 | キルスイッチの作動、または日次損失上限などによる停止。キルスイッチは `resume` まで新規エントリーが止まります |
| PAUSED 新規停止中 (状態不明の注文) | 黄 | 状態不明の注文があるため新規エントリーだけを停止中。解消コマンドが警告欄に出ます |
| DEGRADED 口座取得の劣化 | 黄 | 口座情報を取得できない、または失敗が続いている (新規エントリーを停止中) |
| FX≈ 概算レート使用中 | 黄 | 為替レートが概算のため、該当通貨の新規エントリーを停止中 |
| STALE 更新停止 | 橙 | 表示が古い可能性があります。状態の取得に 3 回連続で失敗した、エンジンの最終 tick から tick 間隔の 3 倍 (不明なら 20 秒) 以上たった、または状態を取得できない時間が長く続いた |


## 取引先の設定 (`.env.local`)

| VENUES の値 | 対象 | 必要な設定 |
|---|---|---|
| `synthetic` | 合成データ (デモ・動作確認用) | なし |
| `gmo` | GMOコイン (取引所のレバレッジ取引。価格の取得と発注) | `GMO_SYMBOLS` (既定 `BTC_JPY,ETH_JPY,XRP_JPY`)。発注には `GMO_API_KEY` / `GMO_API_SECRET` |
| `ccxt` | 暗号資産取引所 (bitFlyer, bitbank, Coincheck, Binance 等、ccxt 対応の取引所) | `CCXT_EXCHANGE`。発注には `CCXT_API_KEY` / `CCXT_SECRET` |
| `oanda` | FX (OANDA v20) | `OANDA_API_TOKEN`, `OANDA_ACCOUNT_ID`, `OANDA_ENV=practice` |
| `alpaca` | 米国株 (Alpaca) | `ALPACA_KEY_ID`, `ALPACA_SECRET_KEY`, `ALPACA_PAPER=true` |
| `dex` | DEX 上のミームコイン (DexScreener)。価格の監視とペーパー売買のみ | `WATCHLIST=dex\|solana:<ペアアドレス>\|meme` |

### GMOコイン (`VENUES=gmo`)

手数料が低く (成行 0.05% 前後、銘柄により異なる。値は API から取得)、レバレッジ取引で live でも売りから建てられます。
- 設定例: `VENUES=gmo`、`GMO_SYMBOLS=BTC_JPY`。キーは `.env.local` に `GMO_API_KEY` / `GMO_API_SECRET` (live と `gmo check` だけで使用)。
- `GMO_LEVERAGE_FEE_DAILY` (既定 0.0004 = 0.04%/日): 日本時間 6:00 をまたいで建玉を持つと、paper と仮想トレードでこの率の手数料を計上します。
- `GMO_MAX_EFFECTIVE_LEVERAGE` (既定 1): 建玉の合計を口座の評価額の何倍までにするか。1 なら借りて大きく張ることはしません (レバレッジは売りから建てるためだけに使う)。
- 決済は必ず決済専用の注文 (`closeBulkOrder`) で行い、反対側の建玉 (両建て) は作りません。
- live では、GMOコインと他の発注先 (ccxt・OANDA など) を同時に使うと、GMOコインの新規の取引を止めます (建玉の上限を GMOコインの口座だけで計算できないため)。
- **live に切り替える前に `npm run trader -- gmo check` を実行してください。** 注文は出さずに API の応答の形を確かめ、想定と違う項目を表示します (この API 対応は公式資料と照合できていない項目があるため)。

### 取引所 (ccxt) の選び方

**bitbank を推奨します** (`.env.example` の既定は `CCXT_EXCHANGE=bitbank`)。bitbank はローソク足を日付ファイル単位で返す仕様のため、必要な本数が揃うまで日付ごとのファイルを順にさかのぼって取得します。バックテストの `--source ccxt` も使えます。

**bitFlyer** は ccxt でローソク足 (OHLCV) を提供していません。そのため次の制約があります。
- 足は気配 (bid/ask) から組み立てます。出来高は 0 になります。
- 組み立てた足の履歴は保存しないため、再起動すると消えます (起動後に貯め直します)。
- バックテストの `--source ccxt` は使えません。

`CCXT_EXCHANGE` を設定しなかった場合の既定値も bitbank です。

### 銘柄

監視する銘柄は `WATCHLIST` に `venue|symbol|assetClass` の形式で、カンマ区切りで指定します。

例: `ccxt|BTC/JPY|crypto,oanda|USD/JPY|fx,alpaca|AAPL|stock`

`ANTHROPIC_API_KEY` を設定すると、ニュース分析・戦略計画・振り返りに Claude を使います。未設定でも、キーワード辞書とルールベースで動作します。

## 運用 (常時稼働)

### 準備

- **Node.js 22.13 以上**が必要です。Ubuntu 24.04 の apt の Node.js は古いので、NodeSource などから入れてください。
- `DB_PATH` は**絶対パス**を推奨します (例: `/var/lib/trader/trader.db`)。相対パス (`./data/trader.db`) は、起動したときの作業ディレクトリが基準です。systemd 経由と手元のシェルで作業ディレクトリが違うと、別の DB を見てしまいます。`report` / `status` などは DB が無いとエラーにします (空の DB を作りません)。
- 設定は `.env.local` (`.env` も読みます) に書きます。`npm start` / `npm run ...` は、実行したディレクトリのこのファイルを読みます。シークレットを含むので `chmod 600 .env.local` を推奨します。

### systemd の例

`/etc/systemd/system/trader.service` (`<...>` は環境に合わせて置き換えてください):

```ini
[Unit]
Description=Trader
After=network-online.target
Wants=network-online.target

[Service]
User=<実行ユーザー>
WorkingDirectory=<trader の絶対パス>
ExecStart=/usr/bin/npm start
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now trader
journalctl -u trader -f          # ログを見る
```

`npm` のパスは `which npm` で確認してください (NodeSource などで入れると `/usr/bin/npm` です)。

### 更新

```bash
cd <trader の絶対パス>
git pull && npm install && sudo systemctl restart trader
```

学習データ (DB) は `.gitignore` の対象 (`data/`, `*.db`, `*.db-*`) なので、`git pull` で消えたり上書きされたりしません。`.env.local` も同様です。

### バックアップ

DB は SQLite (WAL モード) です。動作中に `trader.db` だけをコピーすると、`-wal` ファイルの内容が抜けて不完全になることがあります。次のどちらかで取ってください。

```bash
# 動かしたまま (sqlite3 コマンドが必要: sudo apt install sqlite3)
sqlite3 /var/lib/trader/trader.db ".backup '/path/to/backup/trader-$(date +%F).db'"

# 止めてからコピー (-wal / -shm があればそれも一緒に)
sudo systemctl stop trader
cp /var/lib/trader/trader.db* /path/to/backup/
sudo systemctl start trader
```

バックアップには、必要なら `.env.local` も別に (安全な場所へ) 保管してください。シークレットを含むので、リポジトリには入れないでください。

### スマホなどからダッシュボードを見る

ダッシュボードは既定でローカル (127.0.0.1) にしか公開しません。サーバーのポートを手元に転送して見ます (外部公開は推奨しません)。

```bash
# 手元のポートは任意 (ここでは 18787)。サーバー側は DASHBOARD_PORT (既定 8787)
ssh -N -L 18787:127.0.0.1:8787 <ユーザー>@<サーバーのホスト名または IP>
# → 手元のブラウザで http://127.0.0.1:18787 を開く
```

スマホでは、SSH のポート転送に対応したアプリ (Termius など) で同じ設定をし、ブラウザで `http://127.0.0.1:<手元のポート>` を開きます。

### 二重起動の防止

同じ mode (paper / live) のエンジンは、同時に 1 つしか動きません。DB の中にロックを持ち、15 秒ごとに更新します。動いているエンジンがある状態でもう一度起動すると、エラーメッセージを出して終了します。ロックの更新が 60 秒以上止まっている場合、または同じホストでプロセスがもう存在しない場合は、前回の異常終了とみなしてロックを引き継ぎ、警告と監査ログに残します (`Restart=always` で再起動しても問題ありません)。動作中にロックを失ったときは、二重に動かないよう自分で停止します。

### 運用ログの自動削除

DB が大きくならないよう、学習ループ (1 時間に 1 回まで) が古い運用ログを削除します。

| 対象 | 保持期間 |
|---|---|
| 監査ログ (audit)・収集した情報 (intel)・ブリーフ (briefs)・戦略計画 (plans) | 30 日 |
| 評価額の履歴 (equity) | 180 日 |
| 決済済みの仮想トレード・値動きの予想の答え合わせ (1 件ずつの記録) | 30 日 |

取引の記録と学習データ (腕・パラメータ・調整履歴・情報源の信頼度・各集計) は削除しません。

## 安全装置

- **実弾の二重ロック**: `TRADING_MODE=live` と `LIVE_TRADING_CONFIRM=I_UNDERSTAND_REAL_MONEY_RISK` の両方を設定したときだけ、実際に発注します。どちらかが欠けるとペーパーで起動します。テスト実行中は、設定に関わらず実口座の部品を生成できません。
- **リスク上限** (既定値。`.env.local` で変更できます)
  - 1 トレードの損失は評価額の 0.5%
  - 日次損失が 3% に達したら当日停止
  - 最大ドローダウンが 15% に達したら全決済して停止。`resume` を実行するまで再開しません
  - ミームコインは合計で評価額の 5% まで。流動性が 25 万ドル未満の銘柄には入りません
- **コスト比フィルター**: 期待値幅が「往復手数料 + スプレッド」の 2 倍未満のシグナルは見送ります。
- **学習の暴走防止**
  - パラメータは上下限の範囲内で、1 回に 1 つだけ、約 10% ずつ動かします。
  - バックテストで現行より良い場合だけ採用し、採用後に成績が悪化したら自動で元に戻します。
  - Claude の提案も同じ検証を通します。
- **注文の確認**: 取引所が受け付けただけで約定が確定していない注文は「保留中」として記録し、毎ティック照会します。約定を確認してから記録に反映するので、同じ決済を二重に出すことはありません。
  - 成行が 30 秒たっても約定しなければ取り消します。
  - 取引所が「明確に拒否した」注文と「成立したか分からない」注文 (通信の失敗・タイムアウトなど) を区別します。分からない注文は二重に出さず、照会を続けます。
  - 状態が分からないままの注文が残ったら (約 2 分、または照会 5 回)、新規エントリーだけを止めます。他の銘柄の損切り・利確は続けます。その後は取引所の建玉と 30 秒ごとに照合して、約定したかどうかを確定させます。確定したら新規エントリーを自動で再開します。
  - 保留中の注文は `npm run trader -- orders` で確認できます。取引所の画面で状態が分かった場合は、`orders resolve` で手動で確定させられます (動いているエンジンにも次のティックで反映されます)。
  - 新規エントリーの判定では、約定待ちの注文も保有数・余力・資産クラス上限に数えます。
- **一部約定・手数料**: 一部だけ約定した場合は、約定した分だけを記録し、残りは次のティックで決済します。手数料がベース通貨などで引かれた場合も、クオート通貨に換算して記録します。
- **損切りを止めない**: 口座情報の取得に失敗しても、損切り・利確の判定は続けます。取得の失敗が 3 回続いたら、新規エントリーだけを止めます。キルスイッチの発動中は、残っている建玉の決済を 30 秒ごとに再試行します。
- **建玉の突き合わせ**: 5 分ごとに取引所の建玉と照合します。手動や取引所側のストップで決済された建玉は、追跡から外します (学習には使いません)。live では、エンジンが追跡していない建玉がある銘柄には新規エントリーしません。
- **取引所側のストップ**: OANDA では新規注文に損切り注文 (stopLossOnFill) を付けるので、ツールが止まっても損切りが働きます。ccxt と Alpaca にはこの機能がなく、損切りはツールが動いている間だけ働きます。
- **ダッシュボードは閲覧専用**で、既定ではローカル (127.0.0.1) にだけ公開します。想定外の Host ヘッダーで来たリクエストは拒否します (DNS リバインディング対策)。
- 外部 API のエラーメッセージに含まれる URL と応答本文は、クエリ文字列を取り除き、API キー・トークンらしき文字列 (`token=` や `Bearer ...`、英数字が混ざった 32 文字以上の連続など) を `***` に置き換えます。エンジンが監査ログ・ダッシュボードへ書くエラー文も同じ処理を通します。ただし、ロガー自体は文字列を伏せません。伏せ字の処理を通していない値をログに渡すと、そのまま出力されます。ログを共有するときは中身を確認してください。
- すべての発注・停止・パラメータ変更を監査ログ (SQLite) に記録します。

## 既知の制約

- **live は試験段階です。** 実際の取引所・ブローカーの API (ccxt, OANDA, Alpaca, DexScreener、各ニュース API) とは、開発環境の都合でまだ接続して検証していません。レスポンスの形式は公開仕様に基づいています。次の順で進めてください。
  1. ペーパーモードで、データ取得が正しく動くか確認する。
  2. OANDA の practice 口座や Alpaca のペーパー口座など、デモ口座で注文の流れを確認する。
  3. 少額で live を試す。
- **live は専用の口座 (サブアカウント) で動かしてください。** 評価額には口座の現金と、取引対象の通貨の保有がすべて含まれます。また、利用者が手で持っている建玉や現物がある銘柄には、新規エントリーしません。
- 建玉との照合や `orders resolve` で確定させた約定は、価格が推定になるため学習には使いません。
- bitFlyer は注文に独自の ID (clientOrderId) を付けられません。通信の失敗で注文番号が分からなくなった場合は、発注時刻・売買方向・数量で注文一覧と照合します。条件に合う注文が 2 件以上あれば確定できないので、`orders resolve` で手動で確定させてください。
- ダッシュボードを `DASHBOARD_HOST=0.0.0.0` で公開すると、IP アドレスでのアクセスは拒否されます。その場合は `DASHBOARD_HOST` に実際のアドレスを設定してください。ただし、外部公開は推奨しません。
- DEX (オンチェーン) での実際の発注には対応していません (ウォレットの秘密鍵の管理が必要なため)。DEX のミームコインは価格の監視とペーパー売買のみです。取引所に上場しているミームコイン (PEPE, DOGE 等) は ccxt 経由で実際に売買できます。
- 日本株の発注には対応していません (kabu ステーション API などは今後の拡張候補)。
- 市場データはポーリング (定期取得) です。ミリ秒単位の高頻度売買には向きません。WebSocket 対応は今後の拡張候補です。
- 板情報が必要な `scalp_obi` は、板の履歴が無いためバックテストでは検証できません。そのため学習によるパラメータ調整の対象外です。
