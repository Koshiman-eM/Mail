# 自己学習型の仮想通貨自動売買ツール

仮想通貨 (暗号資産) を自律的に売買するツールです。Solana のトークン・ミームコインを DEX アグリゲーター Jupiter で売買するボット (現物だけ。空売り・レバレッジなし) です。戦略はスキャルピングと短期売買だけです (中期・長期・ミームコイン専用の戦略は廃止しました)。

- **既定の取引先は Jupiter (`VENUES=jupiter`) で、paper (仮想売買) です。** SOL・JUP と、固定のミームコイン (BONK・WIF・POPCAT・MEW) に加え、自動探索で見つけたミームコインを期限つきで監視します (「Jupiter (Solana)」の節)。
- **いまは live の発注先がありません。** `TRADING_MODE=live` にすると起動しません (「live の発注先は未対応です (Jupiter の実弾は次の段階で実装予定)」)。GMOコイン・FX・株式は廃止しました。
- 合成データ (`synthetic`) と ccxt (`CCXT_EXCHANGE`、既定 bitbank) も paper・バックテスト用に使えます。

インターネットから集めた情報で戦略を立てます。損益が出るたびに要因を分析し、その結果を次の判断に反映します (自己学習)。

> **重要**
> - 既定は**ペーパートレード (仮想売買)** です。実際の資金は動きません。
> - 利益は保証されません。スキャルピングは手数料とスプレッドの影響が非常に大きく、多くの戦略はコスト負けします。
> - 実弾で運用する前に、必ず実データでバックテストとペーパー運用を十分に行ってください。少額から始めてください。
> - 自分の資金を自分で運用する用途を想定しています。他人の資金を運用したり、売買シグナルを有償で提供したりする場合は、金融商品取引法上の登録 (投資運用業・投資助言業など) が必要になることがあります。

## 共通コア (`packages/trading-core`)

資産クラスによらない部分 (エンジン・リスク管理・学習・バックテスト・ダッシュボードなど) は、リポジトリの `packages/trading-core` (`@trading/core`) にあります。FX・株式のボットと共有するためです。trader は `"@trading/core": "file:../packages/trading-core"` で読み込み、`npm install` の postinstall がコアの実行時の依存を入れます。

- trader の `src/` の多くのファイルは、コアの同じパスのファイルを再輸出するだけのファイルです。中身はコア側を見てください (`packages/trading-core/CLAUDE.md` に一覧)。
- trader に残っているのは CLI・設定 (`src/appConfig.ts`)・組み立て (`src/engine/setup.ts`)・Jupiter / ccxt / bitbank の相場・暗号資産の情報源などです。
- コアの試験: `cd ../packages/trading-core && npm install && npm test` (trader の `npm install` はコアの開発用の依存を入れないので、コアで `npm install` してから)。

### 戦略

| 時間軸 | 戦略 ID | 表示名 | 資産クラス | 内容 |
|---|---|---|---|---|
| スキャルピング (1 分足) | `scalp_obi` | 超短期・板の偏り | crypto | 板の厚みの偏り・microprice・約定フロー (板情報が必要。Jupiter には板が無いので入らない) |
| | `scalp_vwap_revert` | 超短期・VWAP への回帰 | crypto | VWAP からの乖離の逆張り (レンジ相場向け) |
| | `scalp_momentum_burst` | 超短期・急な動きに追随 | crypto・meme | 出来高急増を伴う直近高値・安値のブレイク (出来高が不明な足では入らない ※) |
| | `scalp_micro` | 超短期・瞬間の勢い | crypto | 5〜10 分で利確・損切りする超短期のモメンタム (成行。コストの条件を満たすときだけ。出来高が不明な足では入らない ※) |
| | `scalp_rebound` | 超短期・下げの中の反発買い | crypto | 15 分足が下降トレンドのときの、1 分足の売られ過ぎからの反発を買う (買いのみ。**既定で観測専用**) |
| | `scalp_pullback` | 超短期・押し目買い / 戻り売り | crypto・meme | 15 分足 EMA20 の傾きで方向を決め、上昇中の 1 分足の押しを買い、下降中の戻りを売る (売りは空売りできるとき = Jupiter では買いだけ。損切りは押しの極値の外側、利確は損切り幅の 2 倍、保有 10〜30 分。コスト条件を満たすときだけ) |
| 短期 (5 分〜1 時間足) | `short_ema_trend` | 短期・EMA トレンド (15 分足) | crypto・meme | EMA9/21 + ADX、押し目でエントリー |
| | `short_rsi_revert` | 短期・RSI 逆張り (15 分足) | crypto・meme | RSI + ボリンジャーバンドの逆張り |
| | `short_breakout` | 短期・ブレイクアウト (1 時間足) | crypto | ドンチャン・ブレイクアウト + 出来高確認 (出来高が不明な足では入らない ※) |
| | `pullback_5m` | 短期・押し目買い / 戻り売り (5 分足) | crypto・meme | `scalp_pullback` と同じ判定を 5 分足で (方向は 1 時間足 EMA20 の傾き。保有 30 分〜2 時間。コスト条件を満たすときだけ) |
| | `pullback_15m` | 短期・押し目買い / 戻り売り (15 分足) | crypto・meme | `scalp_pullback` と同じ判定を 15 分足で (方向は 4 時間足 EMA20 の傾き。保有 1〜4 時間。コスト条件を満たすときだけ) |

- crypto = 暗号資産 (Jupiter の SOL・JUP、ccxt・合成データの銘柄)、meme = ミームコイン (Jupiter の SOL・JUP 以外の銘柄と自動探索の銘柄、`WATCHLIST` で `|meme` と明示した銘柄)。腕 (学習) のキーに資産クラスが入るので、ミームの学習は crypto と別です。
- ※ Jupiter の足は価格のポーリングから作るので、直近の足の出来高は分かりません (`volumeKnown: false`)。出来高を条件に使う戦略は、出来高が不明な足があれば入りません (0 を「出来高が少ない」と読まない。fail-closed)。ccxt・合成データの足では従来どおりです。

戦略 ID の `short` (と時間軸の `short` / `long`) は「短期 / 長期」の時間軸の意味で、売買の向き (買い / 売り) ではありません。ダッシュボードとレポートでは上の「表示名」(日本語) を表示します (ID は環境変数・保存データ・腕のキーにそのまま使うので変えません。対応表は `src/strategies/labels.ts`)。

`scalp_micro` がコストの条件 (利確幅・損切り幅・期待値) で見送ったシグナルは、「見るだけ」の仮想トレード (理由 `strategy_filter:cost` / `:spread` / `:edge`) として記録します。発注・リスク判定・腕の学習には使いません。
戦略は 11 種類です (超短期 6 / 短期 5)。
`scalp_rebound` は既定で観測専用 (`OBSERVE_ONLY_STRATEGIES=scalp_rebound`) です。新しいシグナルは発注せず、仮想トレード (理由 `observe_only`) としてだけ記録します。すでに持っている建玉は、観測専用にしてもこれまでどおり損切り・利確・戦略の決済シグナルなどで管理・決済します。実際に取引させるときは `OBSERVE_ONLY_STRATEGIES` からその ID を外します (空にすると全戦略が取引します)。

#### 廃止した戦略 (`mid_trend_follow`・`long_momentum`・`meme_momentum`)

中期・長期・ミームコインの戦略は廃止しました。古い設定・データはそのまま使えます。

- **学習データは消しません。** 腕・仮想トレード・パラメータ調整などの記録は DB に残ります。廃止した戦略の新規エントリーはしません。
- **保有中の建玉は管理を続けます。** 更新前に建てた建玉は、損切り・利確・トレーリング・読みの管理・転換で決済でこれまでどおり決済します。出なくなるのは、その戦略自身の決済シグナルだけです。転換で決済は、廃止した戦略の主時間足 (中期 4 時間足・長期 日足・ミーム 1 分足) から判定の時間足を決めます (`src/strategies/retired.ts`)。
- **環境変数に残っていても起動します。** `OBSERVE_ONLY_STRATEGIES`・`STRUCTURE_STRATEGIES`・`REVERSAL_EXIT_STRATEGIES` に廃止した ID があると、起動時 (と `npm run status`) に「廃止した戦略 id があります」と警告し、その ID を無視します。`REVERSAL_EXIT_STRATEGIES` の廃止した ID だけは、更新前に建てたその戦略の建玉に効きます (一覧から外すと「空 = すべての戦略」に変わることがあるため)。
コスト差引後の期待値を出す戦略 (`scalp_micro`・`scalp_rebound`・`scalp_pullback`・`pullback_5m`・`pullback_15m`) は、リスク管理のコスト比でコストを二重に数えません: 「期待値 ≥ (`MIN_EDGE_TO_COST` − 1) × コスト (0 未満にはしない) かつ 期待値 > 0」で判定します (テンポの有無によらず同じ。バックテストも同じ)。ほかの戦略は「期待値幅 ≥ `MIN_EDGE_TO_COST` × コスト」です。
`npm run report` の「超短期・瞬間の勢い / 超短期・下げの中の反発買い の答え合わせ」の表は、戦略・見送り理由ごとの利確到達率と、値動きがランダムなときの勝率 p0 を並べます。利確到達率が p0 を安定して上回るなら、値動きに優位性があります。
平均R (コスト前) が正でも平均純R が負なら、手数料が利益を上回っています。件数が少ないうちは偶然の影響が大きいので判断しないでください。

### 「収集した情報」を学習に使う仕組み

1. エントリー時に、判断に使った情報 (どの情報源がどちら向きだったか) をトレード記録に保存します。
2. 決済後、情報の向きと実際の値動きが一致したかを情報源ごとに集計します。
3. 一致率に応じて、情報源の重み (0.2〜2.0) を自動更新します。
4. 次回の情報分析では、この重みで情報源を重み付けします。
5. 資産クラスごとに「情報が損益に効いているか」も測り、情報バイアスが戦略に与える影響の強さを自動で調整します。

### 取引が無い間も学習する仕組み

実際の取引は件数が少ないため、次の 3 つで学習の材料を増やします。どれも発注・リスク判定・建玉管理には関与しません (記録して後で答え合わせをするだけです)。

- **仮想トレード (見送ったシグナルの答え合わせ)**
  - 戦略が売買シグナルを出したのに発注しなかったもの (コスト比フィルター、リスク判定の拒否、方向バイアスとの不一致、腕の無効化、スコア負けなど) を仮想のトレードとして記録します。
  - 毎ティックの気配で損切り・利確・時間切れを判定し、約定ずれ (片道 2bps) とコストを差し引いた R で結果を出します。
  - 結果は、同じ腕 (戦略×相場環境×資産クラス) の配分の更新に**重み 0.25** (実際の取引は 1) で反映します。
  - 戦略自身がコストで見送ったシグナル (`strategy_filter:*`) は観測専用で、保存だけして腕・情報の効き具合には使いません。
  - リスク管理の停止中 (日次損失の上限・キルスイッチ・状態不明の注文による新規停止) に記録した仮想トレードは、学習には使いません。
  - 未決済の仮想トレードは再起動後も続けます。決済済みの記録は 30 日で削除します。
- **ニュースと値動きの答え合わせ**
  - 強弱がはっきりしたニュース (監視銘柄に関係するもの) を記録し、15 分・1 時間・4 時間後の値動きと比べます。
  - ノイズの範囲 (1 分足の ATR 比と往復コストの大きい方) に収まる動きは、当たりにも外れにも数えません。
  - 当たり・外れを情報源の信頼度に**重み 0.3** で反映します。
- **値動きの予想**
  - 監視銘柄ごとに 5 分ごと、15 分・1 時間・4 時間後の「上がる / 下がる / ほぼ動かない」と値幅を予想します。特徴量はトレンド・モメンタム・平均回帰・ニュースのバイアス・戦略の合意で、確定足だけから作ります (先読みしません)。
  - 期限に実際の値動きと答え合わせをし、オンラインのロジスティック回帰で重みを更新します。
  - 予想がエントリーに効くのは、(予想時間, 資産クラス) ごとに、方向を当てた回数が 100 件以上あり、的中率が 50% を統計的に有意に上回る (片側 95%。重なる予想は独立でないため補正) ときだけです。そのときに限り、シグナルと予想の向きが一致すれば最大 1.2 倍、逆なら最小 0.7 倍にエントリーサイズを調整します。有意でない間・予想が「ほぼ動かない」とき・予想が古いときは 1 倍で、まったく影響しません。サイズは最終的にリスク管理の上限 (1.5 倍) の範囲に収まります。

### 学習状態は paper / live で別

腕・パラメータ・調整履歴・情報源の信頼度・ニュースの答え合わせ・値動きの予想・仮想トレードは、mode (paper / live) ごとに別のキーで保存します。paper の学習結果が live に混ざることはありません。

- 旧バージョンのデータ (mode の区別が無かったもの) は、初回起動時に **paper 用へ引き継ぎ**ます (旧データは消しません)。
- **live は初期状態から**始まります (腕・信頼度は事前分布、パラメータはコードの既定値)。
- `report` は、現在の `TRADING_MODE` で解決された mode (paper / live) の学習状態を表示します。

### paper でだけ空売りを再現して学習する (`PAPER_SIMULATE_SHORT`)

bitbank などの現物 (ccxt の spot) は空売りできないため、live では売りのシグナルを出しません。paper では、空売りの成績も学習させるために「売りで負の建玉を持ち、買い戻しで決済する」空売りを再現します (既定で有効)。**live では空売りしません** (設定に関わらず、live の銘柄・リスク管理・実口座の発注の経路は従来のままです)。

- **対象**: 取引所で空売りできない暗号資産 (`allowShort=false` の `crypto`)。`WATCHLIST` で資産クラスを `meme` にした銘柄は、流動性が薄く実際には借りられないため対象外です。取引所で空売りできる銘柄 (`allowShort=true`) は従来どおりです (いまの取引先には無い)。
- **約定と会計**: 売りで負の建玉を持ち、建玉代金を余力から拘束します (証拠金)。買い戻したときに、借入コスト = 建玉代金 (平均建値 × 数量) × `PAPER_SHORT_BORROW_RATE_DAILY` × 保有日数 (日割り) を手数料として計上します。保有中の未払い分は評価額から差し引きます。
  - 既定の日率 0.04%/日は bitbank の信用取引の手数料・金利を想定した**仮の値**です。**実際の料率 (と日数の数え方) は取引所で確認**してください。
- **リスク管理**: 空売りもリスク管理 (`evaluateEntry`) をすべて通します。損切りはエントリー価格より上に置き、最大保有数・1 銘柄上限・資産クラス別の上限に含めます。
- **学習の分離**: 空売り (paper 再現) の取引と仮想トレードは、別の腕 `<戦略>|<レジーム>|<資産クラス>|short` で学習します。買いの腕 (従来のキー) の配分・停止には混ざりません。
  - パラメータ (買い・売り共通) の調整・事後評価と振り返りには使いません (live に持ち込む調整は live で実行できる取引だけで判断するため)。情報源の信頼度・情報の効き具合も更新しません。値動きの予想の「適用した予想」にも数えません。
  - 計画の片側バイアスは、paper では対象の銘柄を「売りのみ」にできます (live では従来どおり「両方」+ リスク縮小)。
- **表示**: `report`・`simulate`・ダッシュボード (取引タブ・学習タブ) で、成績を「買い」「売り (取引所で可能な空売り)」「空売り (paper 再現)」に分けて表示します。**live で実際にできる成績は「空売り (paper 再現)」を除いたもの** (現物なら買いのみ) です。
- 無効にするには `PAPER_SIMULATE_SHORT=false` にします (従来の動作)。保有中の再現した空売りは、無効にした後も決済 (買い戻し) だけはできます。

## 相場構造 (ダウ理論) フィルター

戦略のシグナルを、相場構造 (高値・安値の切り上げ / 切り下げ) の目線と照らして絞ります。既定で有効です (`STRUCTURE_MODE=filter`)。`off` にすると従来と完全に同じ動きです。

- **確定足だけ**を使い、各時間足で直近 300 本を見ます。スイング点 (高値・安値) は N 本後に確定するので、後から書き換わりません。
- 上位足の確認も確定足だけです (1m→15m、5m/15m→1h、1h→4h、4h→1d、1d→1w)。週足は直近 300 本の日足から作り、形成中の週は使いません。
- 目線と逆のシグナル、上位足と食い違うシグナル、ちゃぶつき (目線が短期間に何度も反転) などは見送ります。見送りは観測専用の仮想トレード `strategy_filter:structure_*` (bias / mtf / chop / none / weak / po / stop) として記録するだけで、学習には使いません。
- 既定の対象は `scalp_momentum_burst` / `scalp_micro` / `short_ema_trend` / `short_breakout` です。逆張りや反発を狙う `scalp_obi` / `scalp_vwap_revert` / `short_rsi_revert` / `scalp_rebound` は、目線と逆に入ること自体が設計なので対象外です。押し目買い・戻り売りの `scalp_pullback` / `pullback_5m` / `pullback_15m` も、上位足のトレンドを戦略の中で判定するので対象外です。
- 構造の損切り (`STRUCTURE_STOP_MODE=structure`) は、損切りを押し安値 (売りは戻り高値) の外側 ± ATR × バッファへ動かすだけです。サイズはリスク管理が決め、期待値は増やしません。新しい損切り幅が元の 0.5 倍未満・3 倍超・0.5 ATR 未満のとき、または利確が不正になるときは見送ります。
- 起動時に、未知の戦略 ID・廃止した戦略 ID と、`purist` での `STRUCTURE_EXIT_ON_WEAKENING` を警告します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `STRUCTURE_MODE` | `filter` | `off` / `filter` |
| `STRUCTURE_STRATEGIES` | 上記 7 戦略 | 対象の戦略 ID (カンマ区切り) |
| `STRUCTURE_PIVOT_N` | 6 | スイング点の確定に使う本数 (3〜20) |

| `STRUCTURE_BIAS_METHOD` | `method1` | 目線の判定方法 (`method1` / `method2` / `both`) |
| `STRUCTURE_REVERSAL_MODE` | `purist` | 転換の判定 (`purist` / `conservative`) |
| `STRUCTURE_USE_MTF` | `true` | 上位足の確認を使う |

## 指値 (maker) でのエントリー

新規エントリーを指値にして、手数料を maker にします (`LIMIT_ENTRY`、既定 `true`)。

- 買いは最良の買い気配、売りは最良の売り気配に置きます。優先順位は、シグナル自身の指値価格 > 戦略の指定 (`entryOrder`) > 設定です。`scalp_micro` は成行です。
- post-only は、対応する取引先 (`capabilities.postOnly`。いまはペーパーだけ) で使います。
- リスク判定は発注前に、指値価格でサイズを決めて行います。
- 約定待ちの間は、その銘柄の新規エントリーを止めます。期限切れ・反対のシグナル・損切り価格の通過・新規を止める条件 (停止・日次停止・キルスイッチ・状態不明の注文・口座取得不可・気配の古さ) で取り消します。
- 取り消したら照会で確認します。取消と注文の消滅を確認できるまで追跡から外しません。確認できない場合は状態不明として扱い、新規を止めます。取引所に余分な建玉があれば異常 (キルスイッチ) にします。
- 一部約定は、約定した数量の建玉にします。最小数量未満の端数は追跡せず、監査ログ `limit.dust_entry` に残します。
- 期限切れで約定しなかったものは、仮想トレード `limit_unfilled` (重み 0.25) として記録します。
- ペーパーの約定は、気配が指値を通り抜けたときだけです (触れただけでは約定しません)。手数料は maker です。バックテストも、次の足から高値・安値が指値を通過したときだけ約定し、同じ足では損切りを優先します。検証と CLI のバックテストも、現在の mode と同じ前提です。
- `npm run status` に指値の設定と約定率、`npm run report` に注文種別ごとの成績・maker/taker 手数料の内訳・平均手数料率・指値の約定率を表示します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `LIMIT_ENTRY` | `true` | 新規エントリーを指値にする |
| `LIMIT_ENTRY_TIMEOUT_MS` | 主時間足の長さ (20 秒〜15 分) | 指値の有効期限 (1000〜86400000 ミリ秒) |
| `LIMIT_TAKE_PROFIT` | `false` | 約定後に利確の指値 (reduceOnly) を板に置く。**paper のみ**。live では無視し、起動時に警告します。成行で決済する前に、取り消して確認します |

## エントリー頻度の目標 (テンポ) と最大保有

`TARGET_ENTRIES_PER_HOUR` を設定すると、1 時間あたりのエントリー回数が目標に足りないときだけ、条件を少しずつ緩めます (既定 0 = 無効。無効なら従来と同一です)。

> **注意**
> - **リスクは上がります。** 条件を緩めて入るので、質の低いエントリーが増えます。
> - エントリーが増えても、利益が増えるとは限りません。手数料とスプレッドの負担が増えて、成績が悪化することがあります。
> - 先にペーパーで効果を確認してください。
> - bitbank は taker 手数料が高く、1 分足のスキャルピングはコストの条件をほとんど満たせません。

- **テンポ** (0〜1) = 不足 (1 − 直近 1 時間のエントリー数 / 目標) × 待ち (最後のエントリーから 60/目標 分までは 0、その 2 倍で 1)。ティックごとに 1 回計算し、**新規エントリーの判断にだけ**使います。決済・バックテスト・パラメータ検証には使いません。
- **緩めるもの** (これだけ): 戦略のコスト倍率 (1.5 に向けて)、押し目買い・戻り売りの 3 戦略 (`scalp_pullback`・`pullback_5m`・`pullback_15m`) の閾値 (RSI の距離・上位足の傾きの下限・押しの深さ)、リスク管理のコスト比 (`TEMPO_MIN_EDGE_TO_COST` に向けて。1 未満にはしません)。コストを差し引いた期待値のシグナルは、テンポのときも、そうでないときもコストを二重に数えません (緩めた比率で同じ判定をします)。
- **緩めないもの**: クールダウン、損切り幅の制限、最大保有、リスク管理のそのほかの判定。
- **探索**: ペーパーでは常に、live では `TEMPO_ALLOW_LIVE_EXPLORE=true` のときだけ。コスト差引後の期待値の下限を (テンポ × 往復コスト) だけ下げ、期待値が 0 以下のエントリーはサイズを `TEMPO_EXPLORE_SIZE` 倍にして「探索」として記録します。NaN は常に拒否します。
- **上限**: 直近 1 時間のエントリーが ceil(目標 × `TEMPO_CAP_MULTIPLIER`) に達したら、新規を止めて仮想トレード `tempo_cap` を記録します。数えるのは約定して建玉になったときで、再起動後もこの mode の直近 1 時間の取引と建玉から復元します。
- **最大保有** (`MAX_HOLD_MINUTES`、0 = 無効、5〜1440): 戦略の最大保有をこの分数までに縮めます。保有中の建玉は変えません。バックテストと検証も同じ値を使います。時間軸が中期・長期の戦略は新規を発注せず仮想トレード `hold_limit` (観測専用と同じ扱い。重み 0.25、腕は止めません) として記録する規則も残していますが、いまの戦略に中期・長期はありません。
  - 読みの管理 (`THESIS_EXIT=true`、既定) のときは、この分数は「読みの期限」の上限です。期限で利益が出ている建玉は、期限 × `THESIS_EXTEND_MULT` まで持ち続けることがあります (次の節)。

| 変数 | 既定 | 内容 |
|---|---|---|
| `TARGET_ENTRIES_PER_HOUR` | 0 | 目標のエントリー回数/時 (0〜60。0 で無効) |
| `MAX_HOLD_MINUTES` | 0 | 最大保有の分数 (0 で無効、5〜1440) |
| `TEMPO_MIN_EDGE_TO_COST` | 1 | テンポ時のコスト比の下限 (1 以上) |
| `TEMPO_CAP_MULTIPLIER` | 2 | 上限 = 目標 × この値 (切り上げ) |
| `TEMPO_EXPLORE_SIZE` | 0.5 | 探索のサイズ倍率 |
| `TEMPO_ALLOW_LIVE_EXPLORE` | `false` | live でも探索する |

```bash
# 1 時間 6 回を目標、最大保有 30 分で、合成データを 2 日分ペーパー運転
TARGET_ENTRIES_PER_HOUR=6 MAX_HOLD_MINUTES=30 npm run simulate -- --days 2
```

- `status` とダッシュボードに、目標・直近 1 時間の回数・テンポ・上限到達・探索の可否・最大保有を表示します。
- `report` に、探索 / 通常 (テンポ有効) / 通常 (テンポ無効) の件数・勝率・純損益・平均 R の表を出します。
- `simulate` は、エントリー/時・平均保有・テンポ・見送り件数を表示します。

## 読みの管理 (いつまでに利益が出る読みか)

エントリーするときに「いつ頃までに利益が出るはずか」(**読みの期限**) を決めて、その時間で答え合わせをします (`THESIS_EXIT`、既定 `true`)。

- **読みの期限** = エントリー時刻 + 戦略が出した `expectedMs` (無ければ最大保有)。`MAX_HOLD_MINUTES` があれば、その分数までに縮めます。
- **途中で読み外れ**: 期限の半分を過ぎても値動きが大きく逆行している (手数料・スプレッドを含めない値動きだけで −`THESIS_EARLY_CUT_R` R 以下) なら、期限を待たずに決済します (決済理由「読み外れ(途中)」)。損切りが近い取引でも、コストだけで切ることはありません。
- **期限で読み外れ**: 期限の時点で利益が出ていない (手数料を引いた損益が `THESIS_MIN_R` R 未満) なら決済します (「読み外れ(期限)」)。
- **期限で読み当たり → 延長**: 利益が出ていれば持ち続けます。そのとき損切りを、**建値 (往復の手数料込み)** と **延長してから最も有利な価格から `THESIS_TRAIL_R` R 戻した価格** の高い方 (売りは低い方) へ引き上げます。「最も有利な価格」は延長した時点の価格から測り始めるので、期限より前に大きく伸びてから戻した取引でも、延長した瞬間に決済されることはありません。価格が伸びるほど上がり、下げることはありません。ここに触れたら「トレーリング」で決済します (戦略のトレーリングの調整には使いません)。
- **延長の上限**: 延長しても、期限 × `THESIS_EXTEND_MULT` で決済します (「延長の上限」)。停止していて上限を過ぎてから判定した建玉も、利益が出ていれば「延長」として記録します。
- 一度決めた読みの決済 (読み外れ・上限) は、約定するまで同じ理由で再試行します (その間に価格が戻っても延長しません)。
- 延長後の損切りは保存し、きつくなる方へだけ動かします。設定を変えて再起動しても緩めず、`THESIS_EXIT=false` で再起動しても保存した損切りで守ります。
- 利確・損切り・戦略の決済シグナル・転換で決済は、これまでどおり働きます (読みの決済が決まっている間は、転換で決済は重ねません)。
- R は「当初の損切り幅」を 1 とした損益です。期限の判定は、エントリーで実際に払った手数料と決済の taker 手数料の見積りを引いた損益で行います。ペーパーの空売りの借入コストは含めません。そのため、空売り (paper 再現) の建玉が「建値」で決済されると、わずかな損失になることがあります。
- 延長したかどうかは決済ルールと一緒に保存し、再起動しても続けます (監査ログ `thesis.extended`)。
- 決済は通常の成行の決済と同じ経路です (板に置いた利確の指値は、先に取り消して確かめてから送ります)。
- `THESIS_EXIT=false` なら、これまでどおり最大保有で「時間切れ」にします。最大保有の無い建玉 (以前からの建玉の一部) も従来どおりです。
- live で読みの管理が有効なまま、最大保有のある建玉を引き継いで起動したときは、警告を出して監査ログ `thesis.enabled_live` に残します。
- バックテスト・パラメータの検証・見送ったシグナルの仮想トレードも、同じ規則・同じ時間足で判定します (バックテストは足の終値で判定し、次の足の始値で決済します)。バックテストの基準足が粗くて 1 つ下の時間足を作れないとき (例: 基準足 5 分の `pullback_5m`) は、主時間足で判定します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `THESIS_EXIT` | `true` | 読みの管理を使う (`false` で従来の時間切れ) |
| `THESIS_MIN_R` | 0.1 | 期限で延長する損益の下限 (R、0〜2) |
| `THESIS_EARLY_CUT_R` | 0.5 | 期限の半分を過ぎて、この R だけ逆行していたら途中で決済 (0〜1。0 で無効) |
| `THESIS_EXTEND_MULT` | 4 | 延長の上限 = 期限 × この値 (1〜20。1 で延長なし) |
| `THESIS_TRAIL_R` | 0.5 | 延長後、最も有利な価格からこの R だけ戻したら決済 (0.1〜3) |

- `report` と `simulate` に「読みの答え合わせ」の表を出します (空売り (paper 再現) は件数と純損益を注記します): 途中で読み外れ / 期限で読み外れ / 期限で読み当たり→延長 / 期限前に決着 (利確・損切り・シグナル・転換で決済) の件数・勝率・純損益・平均 R、延長した取引の追加の保有時間と最終的な決済理由、**期限での的中率** (= 延長 ÷ (延長 + 期限で読み外れ))。
- ダッシュボードの保有ポジションに、読みの期限・残り分・状態 (監視中 / 延長中)・現在の R を表示します。`status` には設定と各建玉の読みの期限を出します。

## 転換で決済 (トレンドがはっきり下降に変わったら、利確の手前でも売る)

買いで持っているとき、価格が建値より上がったものの利確の価格には届かず、そこから下げ始めることがあります。その先は利確まで伸びるかもしれないし、下げ続けるかもしれません。
**転換で決済** (`REVERSAL_EXIT`、既定 `true`) は、エントリーしてからの上昇の形が崩れた (ダウ理論でいう **押し安値割れ**) ところで、利確・損切りを待たずに決済します。

例 (買い。建値 100・損切り 97・利確 106、1 分足の戦略。`REVERSAL_EXIT_PIVOT_N=3`):

| 足 (エントリーから) | 終値 | 何が起きるか |
|---|---|---|
| 0 本目 | 100 | 買い (損切り 97・利確 106) |
| 1〜5 本目 | 101 → 103.8 | 上昇 |
| 6〜7 本目 | 103.2 → 102.6 | 押し。7 本目の安値 102.55 が押し安値の候補 |
| 8〜10 本目 | 103.4 → 104.4 | 高値を更新。10 本目 (3 本後) で押し安値 102.55 が確定 |
| 11 本目 | 103.6 | 押し安値より上なので持ち続ける |
| 12 本目 | 102.4 | **終値が押し安値 102.55 を割った** → 次のティックで決済 (利確の手前、含み益のまま) |

そのまま 104.4 から上へ伸びていれば、新しくできた押し安値に水準を上げながら持ち続け、利確 (106) まで届けば利確です。

- 判定に使う時間足は `REVERSAL_EXIT_TF` で決めます。既定の `lower` は **戦略の主時間足の 1 つ下** です (1 分足→1 分足、5 分足→1 分足、15 分足→5 分足、1 時間足→15 分足、4 時間足→1 時間足、日足→4 時間足)。主時間足のままだと、保有時間が短い取引では押し安値ができる前に決済されることが多く、ほとんど働かないためです。`same` にすると主時間足で判定します (従来どおり)。運用では、この時間足の足も自動で取得します。
- 押し安値は、その時間足 (例: 1 分足) で **エントリーした足より後にできたスイングロー** (左右 `REVERSAL_EXIT_PIVOT_N` 本より低い安値) です。左右の本数の分だけ後の足が確定してから使うので、後から書き換わりません。複数あれば一番新しいものを使います (上昇が続けば水準も付いて上がります)。
- 判定は **確定した足の終値** です。ヒゲ (安値) が割っただけでは決済しません。`REVERSAL_EXIT_BUFFER_ATR` を 0 より大きくすると、終値が「押し安値 − その倍数 × ATR(14)」を下回ったときだけ決済します。
- エントリー後にまだ押し安値ができていない間は何もしません (当初の損切りが守ります)。エントリーより前の安値は使いません。
  - `REVERSAL_EXIT_FALLBACK=true` にすると、その間は **エントリーした足の安値** (売りは高値) を水準にします (監査ログに `fallback: true`)。既定は `false` です: 早く発火しすぎて、合成データの simulate ではほとんどの取引をエントリー付近で閉じ、転換で決済の勝率は 5% 前後でした。
- 含み益でも含み損でも同じです。損切りの手前で上昇が崩れたときも、損切りまで待たずに決済します。
- 売り (空売り) は逆です: エントリー後の **戻り高値** を終値が越えたら決済します (戻り高値超え)。
- 損切り・利確・トレーリング・読みの管理 (気配ごと) が先に働きます。同じ足で戦略自身の決済シグナルも出たときは「シグナル」で決済します。読みの管理で延長中の建玉も対象です。
- すべての戦略が対象です (`REVERSAL_EXIT_STRATEGIES` で絞れます)。`REVERSAL_EXIT=false` なら従来と同じ動きです。
- 決済理由は「転換で決済」です (ダッシュボードの取引には「押し安値割れ」「戻り高値超え」を添えます)。判定の根拠 (押し安値・終値・スイングの足の時刻) は監査ログ `position.reversal_exit` に残します。
- バックテスト・パラメータの検証・見送ったシグナルの仮想トレードも、同じ規則・同じ時間足で判定します (バックテストは足の終値で判定し、次の足の始値で決済します)。バックテストの基準足が粗くて 1 つ下の時間足を作れないとき (例: 基準足 5 分の `pullback_5m`) は、主時間足で判定します。
- `STRUCTURE_EXIT_ON_REVERSAL` (相場構造フィルターを掛けた戦略だけの「目線の転換」での決済) とは別物です。両方 `true` にすると重複するので、起動時に警告します。

| 変数 | 既定 | 内容 |
|---|---|---|
| `REVERSAL_EXIT` | `true` | 転換で決済を使う (`false` で従来どおり) |
| `REVERSAL_EXIT_TF` | `lower` | 判定の時間足。`lower` = 主時間足の 1 つ下、`same` = 主時間足 |
| `REVERSAL_EXIT_FALLBACK` | `false` | 押し安値・戻り高値がまだ無いとき、エントリーした足の安値・高値を水準にする (早く発火しすぎるので既定は無効) |
| `REVERSAL_EXIT_PIVOT_N` | 3 | 押し安値・戻り高値の判定の本数 (左右 N 本、2〜10。`STRUCTURE_PIVOT_N` とは別) |
| `REVERSAL_EXIT_BUFFER_ATR` | 0 | 終値がこの ATR の倍数より大きく越えたら決済 (0〜1。0 は越えれば決済) |
| `REVERSAL_EXIT_STRATEGIES` | (空) | 対象の戦略 ID (カンマ区切り)。空ならすべて。未登録の ID は起動時に警告 |

- `report` と `simulate` に「転換で決済」の表を出します: 件数・勝率・純損益・平均 R・含み益で決済した件数・勝った取引が利確までの距離のうちどれだけ取れたか (値動きの R ÷ 計画の利確の R)。`status` には設定を出します。

## Jupiter (Solana)

`VENUES=jupiter` (既定) では、Solana の DEX アグリゲーター Jupiter の価格で paper を動かします。スワップ (署名・送信) はしません (クライアントは読み取り専用)。

- **銘柄**: 固定の銘柄 `JUPITER_TOKENS` (既定 `SOL,JUP,BONK,WIF,POPCAT,MEW`。mint か symbol) と、自動探索 (`JUPITER_DISCOVERY=true`) で見つけたミームコイン。シンボルは `SOL/USDC` の形 (クオートは USDC = USD とみなす。口座通貨は JPY のまま)。SOL・JUP は資産クラス `crypto`、それ以外は `meme`。数量の刻み・最小数量はトークンの decimals から、最小の約定代金は `JUPITER_MIN_NOTIONAL_USD` (既定 $5)。
- **現物だけ**: 空売りしません (paper の空売りの再現 `PAPER_SIMULATE_SHORT` も Jupiter は対象外)。指値もありません (新規は常に成行。`LIMIT_ENTRY`・`LIMIT_TAKE_PROFIT` は Jupiter の銘柄には効きません)。
- **価格と気配**: Price V3 で全銘柄を `JUPITER_POLL_MS` (既定 5 秒) ごとに 1 回で取ります。仲値 = 価格、買い・売り気配は「代わりのスリッページのモデル」(固定 bps + 2 × 代金 / 流動性。主要銘柄 5bps・ミーム 30bps) を代表的な代金 `JUPITER_QUOTE_SIZE_USD` (既定 $50) で評価した価格です。全部の取得に失敗したら新規エントリーを止め、一部の銘柄だけ取れないときはその銘柄の気配が古くなって新規を止めます。
- **約定 (paper)**: 成行は見積もり (`swap/v1/quote`) の実効価格で約定します (15 秒・同じ金額の帯はキャッシュ。取れなければ代わりのモデル)。経路の手数料は見積もりの価格に含まれるので手数料率は 0、手数料は 1 回あたりのネットワーク手数料 `JUPITER_NETWORK_FEE_USD` (既定 $0.02) です。期待値とコストの比較・仮想トレード・バックテストも同じ前提 (代わりのモデル + ネットワーク手数料を代表的な代金で率にした値) です。さらにリスク管理は、サイズを決めた後の実際の代金でのコスト (ネットワーク手数料 ÷ 代金と、代金・流動性による価格影響) でも期待値を確かめ、足りなければ見送ります。気配が 30 秒より古いときは代わりのモデルで約定させず、決済は次のティックで再試行します。
- **足**: 価格から 1 分足を作り (出来高は不明)、上位足はその集約です。起動後に裏で GeckoTerminal (`GECKO_CALLS_PER_MIN`、既定 10 回/分) から履歴 (1 分足と、15 分・1 時間・4 時間・5 分足) を取ります。起動は待たせず、足が揃うまで戦略はシグナルを出しません (6 銘柄で 4 分ほど)。出来高は銘柄を順に回って GeckoTerminal から取り、確定から 3 分以上たった足にだけ入れます。一度出した足の始値・高値・安値・終値は書き換えません (先読み・リペイントをしない。変わるのは「出来高が不明 → 分かった」だけ)。
- **ミームの流動性**: `MEME_MIN_LIQUIDITY_USD` の判定には Jupiter のトークン情報の流動性 (1 時間ごとに取り直す) を使います。3 時間より古い値は「不明」として新規エントリーしません。`MAX_EXPOSURE_MEME` の上限も効きます。
- **自動探索**: `JUPITER_DISCOVERY_MINUTES` (既定 20 分) ごとに、上位のトークン (toptrending・toporganicscore の 1 時間) を選別し (流動性・保有者数・上場からの日数・organicScore・ミント権限 / 凍結権限・上位保有者の比率・疑わしいトークン)、合格した銘柄を期限つき (`JUPITER_DISCOVERY_TTL_HOURS`、既定 6 時間) で監視に加えます。期限まで再合格しなければ外します (保有中・注文中の銘柄は外しません)。監視中の銘柄が後で選別に落ちたら、新規エントリーだけ止めます (建玉の管理は続けます。止めた状態は再起動後も続きます)。同じ symbol の別のトークン (例: TRUMP が 2 つ) は `TRUMP-<mint の先頭 4 文字>/USDC` になり、使ったシンボルは保存するので、再起動しても保有中の建玉の銘柄は入れ替わりません。一覧は DB の kv `jupiter:watch:<mode>` に保存し、追加・削除・不合格の理由は監査ログ (`jupiter.watch_add` / `jupiter.watch_remove` / `jupiter.discovery` / `jupiter.watch_screen_failed`) に残します。
- **USD→JPY**: frankfurter.app の日次のレート (キー不要) を 1 時間ごとに取り直し、最後の値を DB にキャッシュします。取れなければ概算表 (1 USD = 150 JPY) です。
- **学習によるパラメータ調整**: Jupiter の銘柄は長い履歴を取れない (GeckoTerminal の枠では 14 日分の 1 分足を取れない) ので検証できず、調整は適用されません (検証できない変更は適用しない規則のため)。
- **確認**: `npm run trader -- jupiter check` で、各 API の応答の形・既定の銘柄の mint・USD/JPY のレートを確かめます (読み取りだけ。API キーは表示しません)。API の仕様は公式資料の記述に基づくもので、実際の応答とはまだ照合していません。初回は必ず実行してください。

| 変数 | 既定 | 内容 |
|---|---|---|
| `JUPITER_API_KEY` | (空) | API キー (任意)。あればキーありの上限 (既定 1 回/秒) で呼びます。表示・ログには出しません |
| `JUPITER_RPS` | (空) | 1 秒あたりの上限。空ならキーなし 0.5 / キーあり 1 |
| `JUPITER_POLL_MS` | 5000 | 価格の取得間隔 (ミリ秒、1000〜15000。気配の古さの上限 30 秒の半分以下) |
| `GECKO_CALLS_PER_MIN` | 10 | GeckoTerminal の 1 分あたりの上限 (1〜30) |
| `JUPITER_TOKENS` | `SOL,JUP,BONK,WIF,POPCAT,MEW` | 固定の銘柄 (mint か symbol) |
| `JUPITER_DISCOVERY` | `true` | 自動探索 |
| `JUPITER_DISCOVERY_MINUTES` | 20 | 自動探索の間隔 (分、5〜1440) |
| `JUPITER_DISCOVERY_TTL_HOURS` | 6 | 自動追加の期限 (時間、1〜168) |
| `JUPITER_DISCOVERY_MAX_TOKENS` | 10 | 自動追加の最大件数 |
| `JUPITER_DISCOVERY_MIN_LIQUIDITY_USD` | 250000 | 選別: 最低の流動性 |
| `JUPITER_DISCOVERY_MIN_HOLDERS` | 2000 | 選別: 最低の保有者数 |
| `JUPITER_DISCOVERY_MIN_AGE_DAYS` | 3 | 選別: 最初のプールからの最低日数 |
| `JUPITER_DISCOVERY_MIN_ORGANIC_SCORE` | 60 | 選別: 最低の organicScore (0〜100) |
| `JUPITER_DISCOVERY_MAX_TOP_HOLDERS_PCT` | 35 | 選別: 上位保有者の比率の上限 (%) |
| `JUPITER_DISCOVERY_VERIFIED_ONLY` | `false` | 選別: 検証済みのトークンだけ |
| `JUPITER_NETWORK_FEE_USD` | 0.02 | 1 回のスワップのネットワーク手数料 (USD) |
| `JUPITER_QUOTE_SIZE_USD` | 50 | 気配とコストの見積もりの代表的な代金 (USD) |
| `JUPITER_MIN_NOTIONAL_USD` | 5 | 最小の約定代金 (USD) |

API の呼び出しの目安 (1 分あたり): Jupiter は価格 12 回 (5 秒ごと。銘柄が 50 を超えると 2 倍) + 約定の見積もり (約定ごとに最大 1 回) + 自動探索 2 回 / 20 分 + トークン情報 1 回 / 時間 で、キーなしの上限 30 回/分に収まります。GeckoTerminal は起動時に 1 銘柄 6 回 (プール + 5 つの時間足) を `GECKO_CALLS_PER_MIN` の枠で順に取り、その後は残りの枠で出来高を銘柄ごとに最短 1 分おきに取ります。

### サーバーを Jupiter に切り替える手順

1. `sudo systemctl stop trader`
2. `git pull` と `npm install`
3. `.env.local` を `VENUES=jupiter` にし、API キーがあれば `JUPITER_API_KEY=...` を書く (`WATCHLIST` の `ccxt|...` は Jupiter では使いません)
4. `npm run trader -- jupiter check` (応答の形・既定の銘柄の mint・USD/JPY を確認。NG があれば内容を確認)
5. `npm run trader -- paper reset --equity 100000 --confirm` (推奨。以前の bitbank の建玉には価格が来ないため。学習データは残ります)
6. `sudo systemctl start trader`

`VENUES` を書いていない (既定のまま) で合成データ用の DB (`<DB_PATH のベース名>-synthetic.db`) が残っていると、起動時と `npm run status` に「いまは DB_PATH を使う。以前の DB を使うなら VENUES=synthetic」と警告します (以前の既定は synthetic でした。自動では移しません)。

5 を省いても起動はします。いまの `VENUES` に無い取引先の建玉は、起動時のログと `npm run status` に警告が出て、価格が取れないため損切り・決済が動きません (建玉は消しません)。

## 使い方

```bash
# ネット接続なしで全体の動きを確認 (合成データ + 仮想時計で高速にペーパー運転)
npm run simulate -- --days 3
# --hours N (時間単位。--days と併用可) / --seed 1 (乱数のシード) / --step 15 (仮想時計の刻み, 秒)
# --db <ファイル> (既定は memory。DB_PATH と同じファイルは使えません)
npm run simulate -- --hours 12 --seed 7 --step 30 --db ./data/sim.db

# バックテスト (全戦略の比較)
npm run backtest -- --strategy all --days 30
# Jupiter の銘柄のバックテスト (GeckoTerminal の足。--token は mint か symbol、既定 SOL。1 分足の 30 日分は約 44 回の呼び出し)
npm run backtest -- --strategy all --source jupiter --token BONK --days 7

# Jupiter・GeckoTerminal・USD/JPY の応答の確認 (読み取りだけ)
npm run trader -- jupiter check

# 取引所の実データでのバックテスト (CCXT_EXCHANGE の履歴を取得)
npm run backtest -- --strategy short_ema_trend --symbol BTC/JPY --source ccxt --days 60
# 合成データの乱数のシードを変える (既定 1)
npm run backtest -- --strategy all --days 30 --seed 5

# 相場構造フィルターの比較 (詳しくは「相場構造 (ダウ理論) フィルター」)
npm run backtest -- --structure-compare --strategy all

# 情報収集を 1 回実行して内容を確認
npm run trader -- intel

# 実時間で起動 (既定は paper)。ダッシュボード: http://127.0.0.1:8787
npm start

# 成績・学習状態のレポート (現在の mode の学習状態を表示) / 状態確認 / 停止の解除
npm run report
npm run status
npm run trader -- resume

# 約定待ち・状態不明の注文の一覧と、手動での確定 (live 用)
npm run trader -- orders list      # 引数なしの `orders` も同じ
npm run trader -- orders resolve <clientId> --none                                  # 約定していなかった
npm run trader -- orders resolve <clientId> --filled --qty <数量> --price <価格>    # 約定していた
```

- `orders resolve` は、状態不明 (escalated) になった注文だけが対象です。それ以外の保留中の注文を確定させるには `--force` が必要です。`--none` (約定していなかった) で取消に失敗したときは確定せず、保留のまま建玉の照会で確定させます。
- `resume` は、動いているエンジンにも次のティック (数秒以内) で反映されます。再起動は不要です。
- `VENUES=synthetic` だけで起動した場合、記録は `DB_PATH` とは別のファイル (`trader-synthetic.db` のように `-synthetic` が付いたもの) に保存されます。合成データの成績が実データの学習に混ざらないようにするためです。`simulate` は `DB_PATH` とこのファイルのどちらにも書き込みません。
- paper と live の保有ポジション・停止状態は別々に記録されます。paper で作ったポジションを live で決済しようとすることはありません。

## ダッシュボード

`npm start` で起動すると、既定では http://127.0.0.1:8787 (`DASHBOARD_HOST` / `DASHBOARD_PORT`) に閲覧専用の画面が開きます。暗いターミナル風の画面で、5 秒ごとに更新されます。上部のタブで次のように切り替えます。

| タブ | 見えるもの |
|---|---|
| BOARD (ボード) | 全体を一覧する画面。ENGINE LOG (判断の記録: エントリー・決済・見送り・計画・発注・リスク・学習の各イベントを新しい順に表示)、チャート (銘柄と時間足を切り替え。選べる時間足は 1 分・5 分・15 分・1 時間・4 時間・日足のうち、エンジンが扱っているもの)、戦略×相場環境ごとの腕の成績ヒートマップ、戦略ごとの配分倍率、指標、集めた情報の粒子の雲、今回の稼働の戦略別成績、SIGNAL STACK、損益、戦略別の勝率、リスク予算、手数料 |
| 概要 | 評価額、リスク状態、評価額の推移 |
| 強気・弱気 | 資産別の強気・弱気 (バイアス)、戦略計画と集めた情報 |
| ポジション | 保有中のポジション |
| 取引 | 直近のトレードと損益要因、戦略別の成績 |
| 学習 | 損益要因の集計、教訓、パラメータ調整の履歴、情報源の信頼度、腕の成績、仮想トレード (見送ったシグナルの答え合わせ)、ニュースと値動きの答え合わせ、値動きの予想の答え合わせ |

**SIGNAL STACK** は、監視銘柄ごとのカード (WATCH) と、直近のエントリー・決済・見送り (最新 5 件) を新しい順に並べます。WATCH カードには現在値、計画の方向、強気・弱気と信頼度、そして時間ごと (15m / 1h / 4h) の値動きの予想を出します。

- 予想は、方向 (▲ 上 / ▼ 下 / ― ほぼ動かない)、その方向の確率 (%)、値幅 (±%) です。カーソルを合わせると、上昇確率・的中率・予想の根拠 (特徴量ごとの寄与) が出ます。
- 的中率の件数が少ない間は「学習中 · n=件数」と表示します。
- 予想がエントリーサイズに反映されている (統計的に有意と確認できた) ときは LIVE バッジが付きます。

**状態バッジ** (画面上部) と警告欄:

| 表示 | 色 | 意味 |
|---|---|---|
| ACTIVE 稼働中 | 緑 | 通常 |
| KILL SWITCH / HALTED 停止中 | 赤 | キルスイッチの作動、または日次損失上限などによる停止。キルスイッチは `resume` まで新規エントリーが止まります |
| PAUSED 新規停止中 (状態不明の注文) | 黄 | 状態不明の注文があるため新規エントリーだけを停止中。解消コマンドが警告欄に出ます |
| DEGRADED 口座取得の劣化 | 黄 | 口座情報を取得できない、または失敗が続いている (新規エントリーを停止中) |
| FX≈ 概算レート使用中 | 黄 | 為替レートが概算のため、該当通貨の新規エントリーを停止中 |
| STALE 更新停止 | 橙 | 表示が古い可能性があります。状態の取得に 3 回連続で失敗した、エンジンの最終 tick から tick 間隔の 3 倍 (不明なら 20 秒) 以上たった、または状態を取得できない時間が長く続いた |


## 取引先の設定 (`.env.local`)

| VENUES の値 | 対象 | 必要な設定 |
|---|---|---|
| `jupiter` (既定) | Solana の DEX アグリゲーター Jupiter (SOL・JUP・ミームコイン)。**価格の取得と paper 専用** (スワップは実行しません)。上の「Jupiter (Solana)」 | `JUPITER_TOKENS` ほか (キーは任意) |
| `synthetic` | 合成データ (デモ・動作確認用。暗号資産の BTC/USDT・ETH/USDT・PEPE/USDT) | なし |
| `ccxt` | 暗号資産取引所 (bitbank, bitFlyer, Coincheck, Binance 等、ccxt 対応の取引所)。**価格の取得と paper・バックテスト専用** (live の発注はしません) | `CCXT_EXCHANGE` (キーは不要) |

- **live の発注先はありません。** `TRADING_MODE=live` と `LIVE_TRADING_CONFIRM` が揃っていても、起動時に「live の発注先は未対応です (Jupiter の実弾は次の段階で実装予定)」と表示して止まります (fail-closed)。`npm run status` にも同じ警告を出します。
- GMOコイン (`gmo`)・FX・株式は廃止しました。廃止した取引先 (`gmo`・`oanda`・`alpaca`・`dex`) が `VENUES` や `WATCHLIST` に残っていても起動します。起動時 (と `npm run status`) に警告して、その取引先と銘柄を無視します。`.env.local` から外してください。
  - `VENUES` が廃止した取引先だけ (例: `VENUES=gmo`) なら、警告して `ccxt` (`CCXT_EXCHANGE`、既定 bitbank) の相場で paper を動かします。`WATCHLIST` の `gmo|...` の銘柄は無視するので、bitbank の既定の銘柄 (`BTC/JPY`・`ETH/JPY` など、あるものを最大 3 つ) になります。銘柄を選ぶなら `WATCHLIST=ccxt|BTC/JPY,ccxt|ETH/JPY` のように書き直してください。
  - `WATCHLIST` で資産クラスを `fx` / `stock` にした銘柄も、警告して無視します。
  - `GMO_*` と `MAX_EXPOSURE_FX` / `MAX_EXPOSURE_STOCK` は読みません (値が不正でも起動は止めず、起動時と `npm run status` に警告だけ出します)。
- USD 建ての銘柄 (`SOL/USDC`・`BTC/USDT` など) の円換算: `VENUES` に `jupiter` があれば frankfurter.app の日次の USD/JPY (1 時間ごとに取り直し、DB にキャッシュ) を使います。それ以外・取れないときは固定の概算表 (1 USD = 150 JPY、`src/engine/fx.ts`) です。paper はそのまま換算します。live は概算表・古い (5 分超の) レートでは新規エントリーしません (日次のレートは live には使えません。Jupiter の実弾では別のレートの取得元が必要です)。bitbank の JPY 建ての銘柄は換算しません。

### 取引所 (ccxt) の選び方

ccxt は価格の取得・paper・バックテスト (`--source ccxt`) 用です (live の発注には使いません)。**bitbank を推奨します** (`.env.example` の既定は `CCXT_EXCHANGE=bitbank`)。bitbank はローソク足を日付ファイル単位で返す仕様のため、必要な本数が揃うまで日付ごとのファイルを順にさかのぼって取得します。バックテストの `--source ccxt` も使えます。

**bitFlyer** は ccxt でローソク足 (OHLCV) を提供していません。そのため次の制約があります。
- 足は気配 (bid/ask) から組み立てます。出来高は 0 になります。
- 組み立てた足の履歴は保存しないため、再起動すると消えます (起動後に貯め直します)。
- バックテストの `--source ccxt` は使えません。

`CCXT_EXCHANGE` を設定しなかった場合の既定値も bitbank です。

### 銘柄

監視する銘柄は `WATCHLIST` に `venue|symbol|assetClass` の形式で、カンマ区切りで指定します。

例: `ccxt|BTC/JPY|crypto,ccxt|ETH/JPY`

資産クラス (3 つ目) は省略できます (取引所の情報から決めます)。使える資産クラスは `crypto` と `meme` だけです。ccxt の銘柄は DOGE・SHIB・PEPE なども `crypto` です (以前はミームコインを自動で `meme` に分けていました)。`meme` として扱いたい銘柄は `ccxt|DOGE/JPY|meme` のように明示します。`meme` の銘柄は資産クラス別の上限 (`MAX_EXPOSURE_MEME`) と最低流動性 (`MEME_MIN_LIQUIDITY_USD`) のリスク判定を受け、戦略の表で資産クラスに meme のある戦略が取引します (専用の戦略はありません)。

Jupiter の銘柄は `WATCHLIST` ではなく `JUPITER_TOKENS` と自動探索で決めます (「Jupiter (Solana)」)。

`ANTHROPIC_API_KEY` を設定すると、ニュース分析・戦略計画・振り返りに Claude を使います。未設定でも、キーワード辞書とルールベースで動作します。

## 運用 (常時稼働)

### 準備

- **Node.js 22.13 以上**が必要です。Ubuntu 24.04 の apt の Node.js は古いので、NodeSource などから入れてください。
- `DB_PATH` は**絶対パス**を推奨します (例: `/var/lib/trader/trader.db`)。相対パス (`./data/trader.db`) は、起動したときの作業ディレクトリが基準です。systemd 経由と手元のシェルで作業ディレクトリが違うと、別の DB を見てしまいます。`report` / `status` などは DB が無いとエラーにします (空の DB を作りません)。
- 設定は `.env.local` (`.env` も読みます) に書きます。`npm start` / `npm run ...` は、実行したディレクトリのこのファイルを読みます。シークレットを含むので `chmod 600 .env.local` を推奨します。

### paper の口座を作り直す (学習データは残す)

1. エンジンを止める: `sudo systemctl stop trader`
   (動作中のエンジンは口座の状態を上書きするため、動作中はコマンドが拒否します。止めてから約 60 秒たっても拒否される場合は少し待って再実行してください)
2. 確認 (何も変更しない): `npm run trader -- paper reset --equity 100000`
   現在の評価額・新しい評価額・閉じる建玉 (価格)・消す注文や決済計画・書き換えるキーを表示します。
3. 実行: `npm run trader -- paper reset --equity 100000 --confirm`
4. エンジンを起動する: `sudo systemctl start trader`
5. 確認: `npm run status` / `npm run report` (リセット以降の成績。全期間は `npm run report -- --all`、ダッシュボードは戦略パネルのボタンで切り替え)

- 保有中の建玉は最後の価格 (無ければ建値) で「リセットで決済」として記帳上だけ閉じます。この取引は学習 (腕・要因分析・パラメータ調整・振り返り・情報源の信頼度) にも成績の集計にも使いません。
- 残るもの: 取引の履歴・腕の成績・要因分析・パラメータ調整・振り返り・仮想トレード・値動きの予想・ニュースの答え合わせ・情報源の信頼度・ダッシュボードで変更したリスク上限・指値の約定率。
- 作り直すもの: ペーパー口座の現金と建玉・決済計画・保留中の注文・板に置いた利確・リスク状態 (日初・最高の評価額、キルスイッチ・日次停止の解除)。
- リセット中はエンジンのロックを取るため、その間に起動したエンジンは起動しません。
- 記録: 監査ログ `paper.wallet_reset` と kv `paper:resets` (履歴)。TRADING_MODE=live では実行できません (実弾の口座は対象外)。
- 次回以降の新規 DB でも同じ金額から始めたい場合は `.env.local` に `PAPER_INITIAL_EQUITY=100000` も設定してください。

### 更新

```bash
cd <trader の絶対パス>
git pull && npm install && sudo systemctl restart trader
```

学習データ (DB) は `.gitignore` の対象 (`data/`, `*.db`, `*.db-*`) なので、`git pull` で消えたり上書きされたりしません。`.env.local` も同様です。

### バックアップ

DB は SQLite (WAL モード) です。動作中に `trader.db` だけをコピーすると、`-wal` ファイルの内容が抜けて不完全になることがあります。次のどちらかで取ってください。

```bash
# 動かしたまま (sqlite3 コマンドが必要: sudo apt install sqlite3)
sqlite3 /var/lib/trader/trader.db ".backup '/path/to/backup/trader-$(date +%F).db'"

# 止めてからコピー (-wal / -shm があればそれも一緒に)
sudo systemctl stop trader
cp /var/lib/trader/trader.db* /path/to/backup/
sudo systemctl start trader
```

バックアップには、必要なら `.env.local` も別に (安全な場所へ) 保管してください。シークレットを含むので、リポジトリには入れないでください。

### スマホなどからダッシュボードを見る

ダッシュボードは既定でローカル (127.0.0.1) にしか公開しません。サーバーのポートを手元に転送して見ます (外部公開は推奨しません)。

```bash
# 手元のポートは任意 (ここでは 18787)。サーバー側は DASHBOARD_PORT (既定 8787)
ssh -N -L 18787:127.0.0.1:8787 <ユーザー>@<サーバーのホスト名または IP>
# → 手元のブラウザで http://127.0.0.1:18787 を開く
```

スマホでは、SSH のポート転送に対応したアプリ (Termius など) で同じ設定をし、ブラウザで `http://127.0.0.1:<手元のポート>` を開きます。

### 二重起動の防止

同じ mode (paper / live) のエンジンは、同時に 1 つしか動きません。DB の中にロックを持ち、15 秒ごとに更新します。動いているエンジンがある状態でもう一度起動すると、エラーメッセージを出して終了します。ロックの更新が 60 秒以上止まっている場合、または同じホストでプロセスがもう存在しない場合は、前回の異常終了とみなしてロックを引き継ぎ、警告と監査ログに残します (`Restart=always` で再起動しても問題ありません)。動作中にロックを失ったときは、二重に動かないよう自分で停止します。

### 運用ログの自動削除

DB が大きくならないよう、学習ループ (1 時間に 1 回まで) が古い運用ログを削除します。

| 対象 | 保持期間 |
|---|---|
| 監査ログ (audit)・収集した情報 (intel)・ブリーフ (briefs)・戦略計画 (plans) | 30 日 |
| 評価額の履歴 (equity) | 180 日 |
| 決済済みの仮想トレード・値動きの予想の答え合わせ (1 件ずつの記録) | 30 日 |

取引の記録と学習データ (腕・パラメータ・調整履歴・情報源の信頼度・各集計) は削除しません。

## 廃止した機能と更新時の注意

### GMOコイン・FX・株式の廃止 (仮想通貨だけにする更新)

次の機能を廃止しました: GMOコインの取引先 (`gmo`。live の発注・相場の取得・`gmo check`・`backtest --source gmo`・`GMO_*`・持ち越し手数料・実効レバレッジの上限)、資産クラス `fx` / `stock` (合成データの `USD/JPY`・`AAPL`、経済指標による FX・株式のブラックアウト、`MAX_EXPOSURE_FX` / `MAX_EXPOSURE_STOCK`、振り返りの `assetClass:fx` / `assetClass:stock`)。

- **live は起動しません** (発注先が無いため。Jupiter の実弾は次の段階で実装予定)。`TRADING_MODE=live` のままなら `paper` に戻してください。
- **paper は古い `.env.local` のままでも起動します。** `VENUES=gmo` だけなら ccxt (bitbank) の相場で動きます (上の「取引先の設定」を参照)。DB はこれまでと同じ `DB_PATH` を使います。
- **DB の学習データ・記録は消しません・書き換えません。** 資産クラス `fx` / `stock` の取引・仮想トレード・腕 (`…|fx` など)・パラメータ (`params:<mode>:<戦略>:fx`)・情報の効き具合 (`intelInfluence:<mode>:fx`)・振り返り・予想の集計は残り、読んでも例外にしません (表示はそのままの名前)。新しい計画には fx / stock の振り返りを渡しません。
- ダッシュボードのリスク設定の上書き (kv `risk:limits:<mode>`) に `maxExposureFx` / `maxExposureStock` が残っていても無視します。保存し直しても、その値は消さずに残します。
- 値動きの予想の多重検定 (Bonferroni) のグループ数は 12 (予想時間 3 × 資産クラス 4) のままです。使う資産クラスは減りましたが、保存済みの LIVE の判定と同じ基準を保ち、閾値を緩めないためです (入る z ≥ 2.638)。
- **保有中の建玉**: 更新前の GMO の建玉 (paper) は、同じ銘柄 (BTC/JPY など) を ccxt (bitbank) で監視していれば、その相場で損切り・利確・読みの管理を続けます (以後の持ち越し手数料は計上しません。それまでに積んだ分は決済時に払います)。監視していない銘柄の建玉は価格が更新されません (必要なら `paper reset`)。FX・株式の合成データの建玉 (合成データ用の DB) も同じです。

### それ以前の廃止

次の機能は廃止しました: OANDA (FX)・Alpaca (株式) の取引先、ccxt での実弾の発注 (`CCXT_API_KEY` / `CCXT_SECRET` / `CCXT_PASSWORD`)、ミームコインの戦略 (`meme_momentum`)・DexScreener (取引先 `dex`・情報源・`AUTO_MEME_WATCH`)、中期・長期の戦略 (`mid_trend_follow`・`long_momentum`)。

- **DB の学習データ・記録は消しません。** 廃止した戦略の腕・仮想トレード・取引の記録、kv `engine:autoMemeWatch` (自動監視していたミームの一覧) などは DB に残り、読まないだけです。ダッシュボード・レポートでは、廃止した戦略は ID のまま表示します。
- **古い `.env.local` のままでも paper は起動します。**
  - `VENUES` / `WATCHLIST` の `oanda`・`alpaca`・`dex` は警告して無視します。
  - `OANDA_*`・`ALPACA_*`・`CCXT_API_KEY` / `CCXT_SECRET` / `CCXT_PASSWORD`・`AUTO_MEME_WATCH` は読みません (残っていても害はありません。外してください)。
  - `OBSERVE_ONLY_STRATEGIES` などの廃止した戦略 ID は警告して無視します (上の「廃止した戦略」を参照)。`OBSERVE_ONLY_STRATEGIES` の既定は `scalp_rebound` になりました。
- **保有中の建玉**: 廃止した戦略の建玉は、損切り・利確・読みの管理・転換で決済で管理を続けます。DEX の銘柄の建玉 (paper、自動監視で建てたものなど) は価格を取得できなくなるため、損切り・利確が働かず建玉のまま残ります (評価は最後に分かった価格。必要なら `paper reset` で口座を作り直してください)。
- ccxt の DOGE・SHIB・PEPE などは `crypto` として、暗号資産の戦略で取引するようになります (以前は `meme` で、`scalp_momentum_burst` と `meme_momentum` だけが取引していました)。以前と同じにするなら `WATCHLIST` で `|meme` を付けます。

## 安全装置

- **実弾の二重ロック**: `TRADING_MODE=live` と `LIVE_TRADING_CONFIRM=I_UNDERSTAND_REAL_MONEY_RISK` の両方を設定したときだけ、実際に発注します。どちらかが欠けるとペーパーで起動します。テスト実行中は、設定に関わらず実口座の部品を生成できません。
- **リスク上限** (既定値。`.env.local` で変更できます)
  - 1 トレードの損失は評価額の 0.5%
  - 日次損失が 3% に達したら当日停止
  - 最大ドローダウンが 15% に達したら全決済して停止。`resume` を実行するまで再開しません
  - 資産クラス `meme` (`WATCHLIST` で明示した銘柄) は合計で評価額の 5% まで。流動性が 25 万ドル未満の銘柄には入りません
- **コスト比フィルター**: 期待値幅が「往復手数料 + スプレッド」の 2 倍未満のシグナルは見送ります (コスト差引後の期待値を出す戦略は「期待値がコストの 1 倍以上かつ 0 より大きい」。コストを二重に数えないため)。
- **学習の暴走防止**
  - パラメータは上下限の範囲内で、1 回に 1 つだけ、約 10% ずつ動かします。
  - バックテストで現行より良い場合だけ採用し、採用後に成績が悪化したら自動で元に戻します。
  - Claude の提案も同じ検証を通します。
- **注文の確認**: 取引所が受け付けただけで約定が確定していない注文は「保留中」として記録し、毎ティック照会します。約定を確認してから記録に反映するので、同じ決済を二重に出すことはありません。
  - 成行が 30 秒たっても約定しなければ取り消します。
  - 取引所が「明確に拒否した」注文と「成立したか分からない」注文 (通信の失敗・タイムアウトなど) を区別します。分からない注文は二重に出さず、照会を続けます。
  - 状態が分からないままの注文が残ったら (約 2 分、または照会 5 回)、新規エントリーだけを止めます。他の銘柄の損切り・利確は続けます。その後は取引所の建玉と 30 秒ごとに照合して、約定したかどうかを確定させます。確定したら新規エントリーを自動で再開します。
  - 保留中の注文は `npm run trader -- orders` で確認できます。取引所の画面で状態が分かった場合は、`orders resolve` で手動で確定させられます (動いているエンジンにも次のティックで反映されます)。
  - 新規エントリーの判定では、約定待ちの注文も保有数・余力・資産クラス上限に数えます。
- **一部約定・手数料**: 一部だけ約定した場合は、約定した分だけを記録し、残りは次のティックで決済します。手数料がベース通貨などで引かれた場合も、クオート通貨に換算して記録します。
- **損切りを止めない**: 口座情報の取得に失敗しても、損切り・利確の判定は続けます。取得の失敗が 3 回続いたら、新規エントリーだけを止めます。キルスイッチの発動中は、残っている建玉の決済を 30 秒ごとに再試行します。
- **建玉の突き合わせ**: 5 分ごとに取引所の建玉と照合します。手動や取引所側のストップで決済された建玉は、追跡から外します (学習には使いません)。live では、エンジンが追跡していない建玉がある銘柄には新規エントリーしません。
- **取引所側のストップ**: 付けません (いまの発注先は paper だけ)。損切りはツールが動いている間だけ働きます。
- **ダッシュボードは閲覧専用**で、既定ではローカル (127.0.0.1) にだけ公開します。想定外の Host ヘッダーで来たリクエストは拒否します (DNS リバインディング対策)。
- 外部 API のエラーメッセージに含まれる URL と応答本文は、クエリ文字列を取り除き、API キー・トークンらしき文字列 (`token=` や `Bearer ...`、英数字が混ざった 32 文字以上の連続など) を `***` に置き換えます。エンジンが監査ログ・ダッシュボードへ書くエラー文も同じ処理を通します。ただし、ロガー自体は文字列を伏せません。伏せ字の処理を通していない値をログに渡すと、そのまま出力されます。ログを共有するときは中身を確認してください。
- すべての発注・停止・パラメータ変更を監査ログ (SQLite) に記録します。

## 既知の制約

- **live の発注先はありません** (GMOコインは廃止。Jupiter の実弾は次の段階で実装予定)。`TRADING_MODE=live` では起動しません。実際の取引所の API (ccxt、各ニュース API) とは、開発環境の都合でまだ接続して検証していません。レスポンスの形式は公開仕様に基づいています。
- **live は専用の口座 (サブアカウント) で動かしてください。** 評価額には口座の現金と、取引対象の通貨の保有がすべて含まれます。また、利用者が手で持っている建玉や現物がある銘柄には、新規エントリーしません。
- 建玉との照合や `orders resolve` で確定させた約定は、価格が推定になるため学習には使いません。
- ダッシュボードを `DASHBOARD_HOST=0.0.0.0` で公開すると、IP アドレスでのアクセスは拒否されます。その場合は `DASHBOARD_HOST` に実際のアドレスを設定してください。ただし、外部公開は推奨しません。
- 実弾の発注には対応していません。ccxt の取引所 (bitbank など)・Jupiter (オンチェーン) での実際の発注はできません (GMOコイン・OANDA・Alpaca・DEX と ccxt の発注は廃止しました。Jupiter の実弾は次の段階)。FX・株式は扱いません。
- Jupiter・GeckoTerminal・frankfurter の API は公式資料の記述に基づいて実装し、実際の応答とはまだ照合していません。`npm run trader -- jupiter check` で確認してください (キーなしの上限、Price V3 の 1 回の件数、priceImpactPct の単位、GeckoTerminal の無料枠と古い 1 分足をどこまで返すか、既定の銘柄の mint など)。
- Jupiter の銘柄では、出来高を条件に使う戦略 (`scalp_momentum_burst`・`scalp_micro`・`short_breakout`) は入りません (直近の足の出来高が不明なため)。板を使う `scalp_obi` も入りません。
- 市場データはポーリング (定期取得) です。ミリ秒単位の高頻度売買には向きません。WebSocket 対応は今後の拡張候補です。
- 板情報が必要な `scalp_obi` は、板の履歴が無いためバックテストでは検証できません。そのため学習によるパラメータ調整の対象外です。
