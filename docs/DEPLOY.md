# クラウドへの設置手順 (無料構成)

スマートフォン (Android) から、外出先でも使えるようにクラウドへ設置する手順です。
すべて無料プランで動く構成にしています。パソコンでの作業は最初の 1 回だけで、30 分ほどかかります。

## 構成

| 役割 | サービス | 料金 |
|---|---|---|
| アプリ本体 (画面・API) | Render (Free) | 0 円 |
| データベース | Neon (Free) | 0 円 |
| 定期ジョブ (価格の巡回・利益の再計算) | GitHub Actions | 0 円 (非公開リポジトリは月 2,000 分まで。4 時間ごとの実行で月 700 分程度) |
| 翻訳・AI 返信案 (任意) | Claude API | 従量課金 (使った分だけ) |

無料プランの制約:
- **アプリは 15 分使わないと休止します。** 次に開いたとき、表示まで 30 秒〜1 分ほどかかります (データは消えません)。
- **価格の巡回は 4 時間ごと**です。すぐ確認したいときは商品画面の「価格を再取得」を押します。
- データベースの容量は 0.5GB までです (個人利用なら当面十分です)。

## 事前準備

- GitHub のプルリクエストをマージしておいてください (定期ジョブは既定ブランチでのみ動きます)。
- 必要なアカウント: GitHub (作成済み)、Render、Neon。どちらも GitHub アカウントでログインできます。

## 手順 1: データベースを作る (Neon)

1. https://neon.tech を開き、「Sign up」→ GitHub でログインします。
2. プロジェクトを作成します。
   - Project name: `sedori` など
   - Region: **AWS Asia Pacific (Singapore)** (日本から近い地域)
3. 作成後に表示される **Connection string** をコピーします。
   - 「Pooled connection」のチェックは**外して** (直接接続)、`postgresql://...?sslmode=require` の形のものを使います。
   - この文字列はパスワードを含みます。他人に見せないでください。

## 手順 2: アプリを設置する (Render)

1. https://render.com を開き、「Get Started」→ GitHub でログインします。
2. 画面右上の「New +」→「**Blueprint**」を選びます。
3. リポジトリ `Koshiman-eM/Mail` を選びます (表示されない場合は「Configure GitHub」から Render にリポジトリへのアクセスを許可します)。
4. 入力欄が表示されます。
   - `DATABASE_URL`: 手順 1 でコピーした接続文字列
   - `ANTHROPIC_API_KEY`: Claude API キー (後で入れても構いません。空欄でも動きます)
5. 「Apply」を押すと構築が始まります。10 分ほどで完了し、`https://sedori-xxxx.onrender.com` のような URL が表示されます。

## 手順 3: 定期ジョブを有効にする (GitHub Actions)

1. GitHub のリポジトリを開き、「Settings」→「Secrets and variables」→「Actions」を開きます。
2. 「New repository secret」で次を登録します。
   - `DATABASE_URL`: 手順 1 と同じ接続文字列
   - `ANTHROPIC_API_KEY`: (任意) Claude API キー
   - (任意) 自動探索で楽天の相場を使う場合: `RAKUTEN_APPLICATION_ID`・`RAKUTEN_ACCESS_KEY`・`RAKUTEN_REFERER` (手順 5 参照)
3. 「Actions」タブ →「定期ジョブ (価格巡回・自動探索・利益再計算)」→「Run workflow」で一度手動実行し、緑のチェックになることを確認します。
   以後は 4 時間ごとに自動で実行されます。

## 手順 4: Android で使い始める

1. Android の Chrome で手順 2 の URL を開きます。
2. 初回は「初期管理者を作成」画面になります。名前・メールアドレス・パスワード (10 文字以上) を登録します。
3. 画面上部の「インストール」(または Chrome のメニュー →「アプリをインストール」) で、ホーム画面にアプリとして追加します。
4. 「設定」→「通知」→「この端末で通知を受け取る」を押して、通知を許可します。
   価格変動・赤字の見込み・業者からの新着・CAPTCHA 検知などが、アプリを閉じていても届きます。
5. 「設定」→「利益計算」で、送料・手数料・関税率などの既定値を自分の実態に合わせます。

## 手順 5 (任意): 自動探索で国内価格を調べる (楽天市場 API)

「自動探索」は、登録したキーワードで Alibaba.com・AliExpress・1688.com の検索結果 (1 ページ目) を調べ、
国内 (楽天市場) の相場から利益を試算し、条件 (ROI・利益・MOQ・仕入単価) を満たす商品を仕入れ候補に自動で追加します。
国内価格を調べるには楽天市場 API のキーが必要です (未設定でも動きますが、結果はすべて「国内価格なし」になります)。

1. https://webservice.rakuten.co.jp/ (Rakuten Developers) に楽天会員でログインし、アプリ (アプリ ID) を新規作成します。
2. 作成時の「アプリケーション URL / サイト URL」(許可するサイト) に、手順 2 の Render の URL (`https://sedori-xxxx.onrender.com`) を登録します。
   2026 年からの新しい API は、この URL をリクエストの Referer として検証します。
3. 発行された **applicationId** と **accessKey** を控えます (accessKey はパスワードと同じく秘密にしてください)。
4. Render の `sedori` →「Environment」に次を追加します。
   - `RAKUTEN_APPLICATION_ID`: applicationId
   - `RAKUTEN_ACCESS_KEY`: accessKey
   - `RAKUTEN_REFERER`: 手順 2 で登録したサイト URL (空欄なら Render の公開 URL を自動で使います)
5. GitHub の「Settings」→「Secrets and variables」→「Actions」にも同じ 3 つを登録します。
   GitHub Actions には Render の URL が分からないため、**`RAKUTEN_REFERER` は必ず登録**してください。
6. アプリの「設定」→「巡回」の「国内価格の取得元」で「楽天市場: 設定済み」になっていることを確認します。

注意:
- 楽天の新 API のエンドポイント・パラメーター名はこのアプリの開発時点で実物を確認できていません。
  「楽天 API へのリクエストが不正です」などのエラーになる場合は、Rakuten Developers の API ドキュメントで
  商品検索 API の URL を確認し、`RAKUTEN_ITEM_SEARCH_URL` に設定してください (https の rakuten.co.jp の URL のみ使えます)。
  accessKey の渡し方は `RAKUTEN_ACCESS_KEY_MODE` (`both` / `param` / `header`) で変えられます。
- **Amazon**: 価格取得に使える Product Advertising API 5.0 は 2026 年に廃止されました。後継の Creators API は
  売上実績のあるアソシエイトのみが使え、仕様を確認できていないため対応していません。
- **価格.com**: 公式 API が無く、利用規約上スクレイピングもしないため対応していません。
- 国内価格は楽天の検索結果から外れ値 (付属品・まとめ売り) を除いた**下位 25% 点** (中央値より低め) を採用します。
  まとめ売り・セット商品が多いキーワードでは相場がずれることがあるため、探索結果の「根拠」を確認してください。
  `ANTHROPIC_API_KEY` を設定すると、Claude が明らかに無関係な販売例を除外し、海外サイト用のキーワードも自動で翻訳します。
- 海外サイトの検索結果ページは CAPTCHA で止められることがあります。検知した場合は自動突破せず、そのサイトの巡回を停止して通知します
  (「設定 → 巡回」から再開)。アプリの「今すぐ探索」はブラウザ無しの HTTP 取得のため、定期ジョブ (Playwright) より止められやすいです。
  検索結果の読み取りは公開情報から推測したページ構造に基づいており、実サイトの構造が違う・変わった場合は「検索結果を読み取れませんでした」になります。
- 「今すぐ探索」は同じ条件につき 10 分に 1 回まで、定期ジョブでは 1 条件・1 サイトにつき検索結果 1 ページ (最大 30 件) だけを取得します。

## 日々の使い方 (Android)

- **商品を追加する**: Alibaba / 1688 / AliExpress のアプリやブラウザで商品を開き、「共有」→「越境せどり」を選ぶと、
  商品名・価格・業者を読み込んで登録し、利益を自動計算します。アプリ内の「URL から追加」に貼り付けても同じです。
- **自動探索**: 下のタブの「探索」で、キーワード・想定重量・自動追加の条件 (最低 ROI など) を登録します。
  4 時間ごとの定期ジョブで探索し、条件を満たした商品は仕入れ候補に自動で追加され、通知が届きます。
  条件に届かなかった商品も理由付きで一覧に残り、「追加」「除外」できます。利益計算の画面は「仕入れ候補」画面のボタンから開けます。
- **業者のメッセージを取り込む**: 業者アプリでメッセージを長押し → 共有 (またはコピーしてアプリに貼り付け) → 「業者メッセージとして取り込む」。
  日本語訳と AI 返信案が作られます。
- **返信する**: 返信案を確認 (または自分で書いて) 承認 →「アプリで送る」で業者アプリを選んで送信 → 戻って「送信しました」を押すと記録されます。
  このアプリが業者へ自動で送信することはありません。

## うまくいかないとき

- **商品情報が読み込めない (「取得失敗」)**: Alibaba などはクラウドからのアクセスを CAPTCHA で止めることがあります。
  その場合は商品画面の「ページのソースを貼り付けて読み込む」を使うか、価格などを手入力してください。
  定期ジョブで CAPTCHA を検知すると、そのサイトの巡回を自動で止めて通知します。「設定 → 巡回」から再開できます。
- **翻訳されない / 返信案が「スタブ」になる**: `ANTHROPIC_API_KEY` が未設定です。Render のダッシュボード →
  `sedori` →「Environment」で設定すると、自動で再起動して反映されます。
- **アプリが開くのが遅い**: 無料プランの休止からの復帰です。1 分ほど待つと表示されます。

- **通知が届かなくなった**: 通知用の鍵 (VAPID) はアプリが自動で作り、データベースに保存しています。
  `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` を自分で設定する場合は、**Render と GitHub Actions の両方に同じ値**を設定してください
  (片方だけだと、定期ジョブからの通知が送れません)。通常は設定不要です。

## 費用を払って改善する場合 (任意)

- Render の Web を有料プラン (月 7 ドル程度) にすると休止しなくなります。
- Redis (Render Key Value など) を追加して `REDIS_URL` を設定し、`npm run worker` を常駐させると、
  価格の再取得がキュー (BullMQ) で処理され、通知も即時に画面へ届くようになります。
