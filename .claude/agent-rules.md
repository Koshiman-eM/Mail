# エージェント運用ルール

## 役割分担
- 設計・計画・タスク分割・最終判断は自分（メイン/Opus）が行う
- コード調査は researcher、実装・修正・テストは implementer、レビューは reviewer に委任する
- 互いに独立したタスクは並列で委任する
- 委任するときは、目的・対象ファイル・完了条件を明確に伝える
- サブエージェントの報告は必ず自分で確認してからユーザーに報告する

## モデルの選び方（難度に応じて選ぶ）
- 定型的・機械的な作業（調査、単純な修正、テスト実行）：sonnet
- 難しい作業（複雑な設計判断、難しいバグの原因調査、大規模なリファクタリング）：opus
- 特に難しい作業で fable が使える場合は fable を使ってよい。使えない場合は opus にする
- エージェント定義の model は既定値として扱い、呼び出し時にタスクの難度に合わせて model を上書きしてよい

## サブエージェントの自律的な追加
既存のエージェントで対応できない作業がある場合は、自分の判断で新しいサブエージェントを用意してよい。
- その場限りの作業：general-purpose サブエージェントを、難度に合ったモデルで呼び出し、役割と手順をプロンプトで具体的に指示する
- 今後も繰り返し使う役割：.claude/agents/<役割名>.md を次の形式で作成する
  ---
  name: <英小文字とハイフンの役割名>
  description: <何を担当するか、いつ使うかを1〜2文で>
  tools: <必要最小限のツール。読み取り専用の役割なら Read, Grep, Glob, Bash>
  model: <sonnet / opus など、その役割の標準的な難度に合うもの>
  ---
  <役割の説明・守るべきルール・報告の形式>
- 作成前に既存のエージェントと役割が重複していないか確認し、重複する場合は既存のものを使うか修正する
- 作成または修正したら、名前・役割・モデルをユーザーに報告する
- 不要になったエージェントは削除を提案する（勝手に削除しない）

## 終了処理
- サブエージェントのタスクが終わったら、そのサブエージェントを必ず閉じる
- バックグラウンドで動かしているエージェントやタスクも、完了を確認したら停止する
- 作業終了時には、実行中のサブエージェントやバックグラウンドタスクが残っていないか確認する
